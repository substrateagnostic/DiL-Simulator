## Project

**TRUST ISSUES: A Trust Officer Simulator** — a satirical office RPG built with Three.js and Vite. No framework; pure vanilla JS ES modules.

### The naming law — EXECUTED 2026-08-04, no longer a constraint

For most of the project's life a **save-safety naming ledger** (`.claude/plans/proposals-whats-missing.md`, now history) froze three internal ids that did not match their display names. Alex ruled live saves burnable on 2026-08-01 and the sweep landed on **2026-08-04**:

| was | is | display name |
|---|---|---|
| `ross`, `ross_boss` | `skip`, `skip_boss` | Skip Hartley / Skip Hartley (Unhinged) |
| `rachel`, `rachel_boss` | `meredith`, `meredith_boss` | Meredith Sterling / Meredith Sterling, SVP |
| `rachel_to` | `rachel` | Rachel (the friendly cubicle-farm trust officer) |

Everything id-derived moved with them in one commit: every flag (`ready_for_skip`, `skip_speech_ready`, `skip_rallied`, `skip_post_karen/chad`, `janitor_needs_skip`, `defeated_skip_boss`, `meredith_fight_started`, `met_meredith`, `skipAngerDebuffTotal`, …), the room ids `skip_office` / `skip_office_large`, every dialog id, `ENEMY_STATS` / `ENEMY_ABILITIES` / `balance.json` rows, `MESHY_MODELS` + the GLB filenames (`skip_boss_idle.glb`, `meredith_boss_idle.glb`), the portrait stems (`skip*.png`, `meredith*.png`, `rachel.png`), the DevPanel presets, and every tool harness.

**Two things this does NOT change**, both deliberate:
1. The `speaker` strings in `src/data/dialogs` were already the display names (`'Skip Hartley'`, `'Meredith Sterling'`, `'Rachel'`) — `SPEAKER_COLORS` and `PORTRAIT_KEYS` keys are unchanged; only the portrait **stem values** moved.
2. Review artefacts under `art/char_refs/` and `screenshots/` (both gitignored, both frozen history) kept their old filenames, so a handful of `ross_*` / `rachel_*` filenames survive in `art/MESHY_WAVE.md` and `art/PROMPTS.md` log rows on purpose. `.claude/plans`, `alexmemory.md` and `art/drafts/` are history and were not swept.

**No migration shim exists and none should be written.** A pre-rename save loads: `Player.deserialize()` defaults everything and every unknown flag simply reads false, so the player lands in a valid-but-early state rather than a crash. The one hard edge was `currentRoom: 'ross_office'` — `RoomManager.loadRoom()` tears the old room down *before* it discovers the new id is missing, so it returned `null` onto an undefined `tileMap`. `ExplorationState._loadRoom()` now falls back to `FALLBACK_ROOM` (`parking_garage`) on any unknown room id. Keep that guard: it protects every future room rename too.

There is no unit-test suite, but `npm run check` is now four gates, and the first two
are the ones this codebase did not have for most of its life: **`dialogs:check` fails if
the generated dialog module has been hand-edited or is stale**, and **`story:sim` fails if
the story graph cannot be completed from a fresh save**. Beyond that, verification is
manual playtest plus the harnesses in `tools/`.

### Balance & Room Editor

`npm run editor` runs `scripts/editor.js` — a plain Node.js HTTP server. Open **http://localhost:3747** for an 11-tab editor: Player, Abilities, Enemies, Allies, Shop, Rooms, Combat Sim, Encounters, Characters, Dialogs (read-only), Diff. Changes write to the override JSON files in `src/data/`; Publish button commits and pushes them. The editor is never included in the Vite build and players cannot access it.

#### Drag-and-drop furniture (Rooms tab)

In the Rooms tab, furniture and NPC dots on the canvas can be dragged to new positions. The canvas updates in real-time as you drag (2D top-down view). Cursor changes to `grab` when hovering near an item and `grabbing` while dragging. Positions snap to 0.5 tile increments. Rotation can be set via the edit panel, the preset buttons, or **R** (rotate selected 90° clockwise). Since the Andrew harvest (2026-08-18, re-implemented from his `ea7d624`/`bb552da`): **scroll-wheel zoom** (0.4×–4.0×, live % display), **NPC facing arrows** (orange; drawn with the VERIFIED θ→(sin, cos) convention — Andrew's original negated cos because it was written against the pre-2026-08-04 inverted doc, so every arrow pointed 180° out), **exit-tile overlay** (green squares, → glyph at ≥ ~80% zoom), **undo/redo** (Ctrl+Z / Ctrl+Y, 50-step stack per room, resets on room switch), and an **Auto-save on drop** checkbox (default OFF — Andrew's own later commit removed unconditional auto-save because every write full-reloads a running `npm run dev` via HMR, which kills the live preview below; the toggle keeps the feature honest).

#### SSE live preview (both servers running)

```bash
npm run dev     # game at localhost:5173 (open with ?dev)
npm run editor  # editor at localhost:3747
```

The editor broadcasts drags/rotates over SSE (`GET /api/live`, CORS-open; the editor page POSTs `/api/live-move`) and a game tab in DEV_MODE subscribes (`src/dev/LiveEditorClient.js`, connected from `ExplorationState.enter()`). **The client applies a move by mutating the imported `room-overrides.json` module object and re-running `_loadRoom()` in place (debounced ~220 ms, player kept where they stand) — NOT by nudging a mesh**: `Room.build()` ends in `_mergeStatics()`, so there is no per-piece mesh left to move, and only a rebuild keeps collision, interactables, seats, contact shadows and wall-art snapping true. Undo/redo/reset broadcast a whole-room `sync` so the preview can move *back*. Staged changes live in memory only — **Save Room Overrides** still persists to disk (and then Vite full-reloads, which is fine because the file now matches). The client module is bundling-proof dev-only: its sole importer is a dynamic import behind `import.meta.env.DEV && DEV_MODE`, which `vite build` folds to false — `dist/assets/*.js` greps clean of `api/live`/`EventSource` (checked by `tools/_ah-editor-demo.mjs`, which also drives a real canvas drag end-to-end and asserts the game-side rebuild).

### Dev Mode

Append `?dev` to the game URL to enable dev mode (e.g. `http://localhost:5173/?dev`). Has no effect on normal play — the flag is read once from `URLSearchParams` in `src/utils/constants.js` (`DEV_MODE`).

**In combat** — press `` ` `` (backtick) during your turn: instantly kills the enemy and routes through the normal victory path, so XP, story flags, and post-dialogs all fire correctly.

**In exploration** — press `F2`: opens a dev panel with two sections:

- **Save Scum** — three save slots with Save and Load buttons. Save writes the current state to that slot and marks it active (future auto-saves go there). Load deserializes the save, reloads the room, and calls `syncFromPlayerState()`. The active slot is highlighted with ★.
- **Quest Skip** — seven cumulative act presets. Clicking a preset writes directly to `player.flags`, then calls `_syncActFromFlags()` and `_refreshStoryProgress()`. Some narrative read-flags are not included, so a small number of NPC dialogs may replay, but all room gates, NPC conditions, and act routing will be correct. **Since P8 that replay set is slightly wider**: a code-pushed scene's once-guard is its own `read_<sceneId>`, so a preset that sets a record flag (e.g. `visited_archive`) without the matching read flag re-offers that scene. Real saves are unaffected — `read_<dialogId>` has been written for every dialog that showed a node since the game shipped. A preset or fixture that jumps past a scene should set its read flag.

| Act 2 — Branch Chosen (finale) | 2 | + `branch_chosen`, all three Henderson defeat flags |
| Act 3 — Hendersons Defeated | 3 | + `act2_complete`, all Henderson/Act 2 defeat flags |

**Two preset laws, both earned:** (1) the *label must match the act the flags actually derive* — `branch_chosen` alone lifts you to act 2, so the old "Act 1" preset landed in Act 2 and the real Act 1 was unreachable from the panel; (2) a preset must leave every room's NPC conditions **mutually exclusive**, because entries share an id and gate on a single flag/notFlag pair — a half-set state spawns two of the same character inside each other (the archive Janitor and Skip both did). `node tools/_ux-dev.mjs` applies every preset through the shipping path and counts duplicate visible NPCs across all 28 rooms; it must report **0**. It runs an **eighth, synthetic post-game state** (act7 + `algorithm_defeated` + `renovation_penthouse`) on top of the seven presets, because the story presets stop at Act 7 and the `penthouse_bar` cast is post-game — without it the census never looks at six of the placements.
  - **It also runs a CROSS-ROOM pass, and that must report 0 too.** The within-room count cannot see the same id being *simultaneously placeable in two different rooms*, which is how the Intern came to be seated at his cubicle-farm workstation while also rehearsing at the head of the conference table one door away. Two classes are **accepted and reported by name, never silently swallowed**: `_resolveRoomId` variant pairs (`skip_office`/`skip_office_large`, `penthouse`/`penthouse_expanded`) are ONE room with two layouts and are collapsed before counting; and the `penthouse_bar` off-shift set — six allies seated in a post-game wing behind a 10,000,000 AUM renovation while each also stands in the room they work in — is convention, because this game has never simulated one body per character and the player is only ever in one room. Anything else needs a row in the tool's `KNOWN` map **with a reason**, which is a producer decision and not a way to make a number go green. Two rows are there now: the Janitor's unconditional garage patrol (pre-existing since ship), and a Grandma pair that only a preset can reach (`chad_defeated && !skip_post_chad` closes before `act2_complete` opens the conference-room entry).

## Architecture

### Core Loop (`src/main.js`)

`Game` boots the engine, pushes `TitleState`, then transitions to `ExplorationState` on start/continue. The main loop calls `InputManager.update()`, `updateTweens(dt)`, and `stateManager.update(dt)` every frame.

### Singletons (`src/core/`)

- **`Engine`** — Three.js renderer, scene, orthographic isometric camera. States that own their own scene call `Engine.renderScene(scene, camera)` + `Engine.skipDefaultRender()` to bypass the default render.
- **`EventBus`** — Simple pub/sub. `on()` returns an unsubscribe function.
- **`GameStateManager`** — Pushdown automaton stack. States implement `enter/exit/pause/resume/update(dt)`.
- **`InputManager`** — Keyboard state tracker. Use `isJustPressed()` / `isConfirmPressed()` / `isCancelPressed()`.
- **`AudioManager`** — Music and SFX playback.
- **`SaveManager`** — localStorage persistence, plus **the carry contract** (`CARRY_VERSION`, `EXPORT_MAGIC`, `FLAGS_OF_RECORD`). Export is deliberately NOT the save blob: the envelope is `{ fmt, fmtVersion, saveVersion, exportedAt, carry, save }`, where `carry` is a small, stable, hand-readable block a LATER CHAPTER reads and `save` is the raw C1 blob passed through verbatim (A3's no-save-format-change ruling) and re-entered through the same `migrate()` ladder as any slot. `.claude/plans/ch2/SEASON_SHEET.md` producer round 6 is why: C2 cold-opens from a card the player saved out of C1, and S3 opens from C2's moral band, so `carry` reserves `moralBand` and `breaches` (C1 writes `null` / `0`) alongside `ending`, `act`, `ngPlus`, `party`, `voiceCounts` and a WHITELIST of story flags. **Three rules for editing `carry`: additive only — never rename, remove or repurpose a key, and every reader must ignore keys it does not know; no whole-blob flags — `carry.flags` is `FLAGS_OF_RECORD`, because every dialog choice writes a permanent `_chose_…` flag and a completionist blob is thousands of keys of noise (measured: carry 10 keys against the save's 1,216); no save-format change.** `encodeExport`/`decodeExport` gzip+base64 behind a `TI1-` prefix whose second character says which path was taken, so a code made on one platform always decodes on another — 46,530 chars of JSON becomes 5,845. UI is `MenuState`'s **Transfer Save** panel (the record-of-service card + the code + copy/download/import); Escape closes it and Enter does NOT, because the box is a textarea. Auto-save fires after every room transition and every story combat victory. `ExplorationState._autoSave()` posts "Game saved." as **`BOOKKEEPING`** — the lowest claim in the game, a small dim strip bottom-left, structurally incapable of being co-visible with a character's line.
- **`NotificationArbiter`** — **the single owner of every transient text surface.** See the dedicated section below. Nothing may create a floating text box by hand any more; post to the arbiter.
- **`AchievementManager`** — Checks and unlocks achievements stored in a separate localStorage key. Call `AchievementManager.check(player, { event: 'event_name' })` after key game events. Shows a toast on unlock. Event strings in use: `combat_victory`, `power_move_used`, `brace_success`, `retaliate_used`, `weakness_hit`, `second_wind_used`, `desperate_gamble_used`, `all_in_used`, `combo_hit`, `perfect_brace`, `shop_purchase`, `client_accepted`, `client_declined`.

### State Stack (`src/states/`)

- **`TitleState`** — Title screen; calls a callback with `'new'` or `'continue'`.
- **`ExplorationState`** — Top-down isometric world traversal. Exit tiles take priority over NPC interactions when the player stands on them. Handles auto-save, AUM award on client acceptance, and shop access.
- **`CombatState`** — Turn-based combat; owns its own Three.js scene via `CombatScene`. Pushed on top of `ExplorationState` and popped when combat ends via `onEnd(result)` callback. On story victory: restores player HP and MP to max, then auto-plays `encounter.postDialogId` if defined.
- **`DialogState`** — Pushed over exploration/combat for NPC conversations. Processes a flat array of nodes (`text`, `choice`, `condition`, `action`, `end`). Choice nodes use the `prompt` field for question text. Text/choice nodes support a `next` property for arbitrary index jumps. Space bar is intentionally blocked when choices are visible — only Enter or mouse click confirm a choice. Every pick persists a `_chose_<dialogId>_<node>_<choice>` flag so revisits render that option greyed and the cursor parks on the first untried one — **except for the dialogs in `KNOWLEDGE_GATE_DIALOGS`** (`compliance_crossword`, `janitor_riddle_1/2/3`), where that memory is an answer key: wrong answers dim permanently and the cursor walks you to the untried one, so mashing Enter brute-forces the Archive password. Quiz dialogs write no `_chose_` flag and never render a choice as seen. Presentation only — no gate, flag or retry path changes. **THE SAFE EXIT (B1).** Escape still only skips the typewriter on a story tree — aborting mid-tree skipped `set_flag`/`start_combat` while still writing `read_<id>`, and that ban stands. A SECOND Escape on a finished line LEAVES the conversation only where `_isBailSafe()` has proved it is lossless: nothing consequential has fired this session (`_sideEffectFired`, set by every `action` and every `stage` node) AND no `action`, no `stage` and no flag-writing choice is reachable from the current node. A bail deliberately does NOT write `read_<dialogId>` — the conversation did not happen, and routers act on that flag. `DialogBox.canExit` is re-asserted per node and the hint reads `[ESC] Leave` only where the exit exists. Coverage off the corpus: **101 of 291 trees bail-safe from node 0, 202 of 291 with at least one bail-safe text node.**
- **`ClientReviewState`** — DOM UI pushed after winning a Reception encounter. Shows the generated client's financials; player accepts or declines, firing `onDecision(accepted)`.
- **`ShopState`** — Supply shop UI; pushed from ExplorationState when player interacts with `type: 'supply_shop'` furniture (break room). Sells consumables, permanent stat upgrades, and office décor using AUM.
- **`MenuState`** — Pause/inventory menu. Tabs: Stats, Abilities, Cosmetics, Journal (enemy log), **Log** (message log), Achievements, Save Game. The **Log** tab reads `NotificationArbiter.getLog()` — the last 40 posts with the arbiter's verdict on each (`shown` / `held until it was safe` / `merged` / `missed`). It carries an unread badge, because deferral is only honest if the player can see that something was held. Opening the menu **suspends the `world` scope** (as do ShopState, DayState and ClientReviewState): a modal owns the screen and a queued toast must not float over it. "Journal" not "Bestiary". Stats tab shows level, XP bar, HP/Coffee/ATK/DEF/SPD bars, AUM, upgrade points, and death counter.
- **`ArcadeState`** — **SPRINT REVIEW**, the break-room cabinet minigame. Self-contained; owns its own Three.js scene (`Engine.renderScene` + `skipDefaultRender`). Modules live in `src/arcade/` — see the "Arcade (`src/arcade/`)" section below.
- **`WardrobeState`** — **THE WARDROBE MIRROR**, the sixth-floor bathroom's `wardrobe_mirror` interactable. The mirror over the basins IS the cosmetics preview: Andrew's live procedural exploration model, rebuilt on every equip through `Player.equipCosmetic`/`unequipCosmetic` — **the equip code is NOT forked**; MenuState's Cosmetics tab and this screen call the same two Player methods, so `getCombatStats()` and the world mesh are correct the moment either surface closes. Own scene via `Engine.renderScene` + `skipDefaultRender` (ArcadeState pattern), tilt-shift suspended for the duration, `suspendScope('world')` per the full-screen-surface law, input POLLED from `update()` (the DifficultyPanel law), CSS injected `wd-`-prefixed (the arcade `Hud.js` precedent — `styles/menu.css` stays untouched). Shows UNLOCKED cosmetics only; the pause-menu tab remains the full catalogue with `???` cards. Writes `wardrobe_mirror_used` on enter and `wardrobe_tip_shown` + one PROGRESS teach ("Pause Menu → Cosmetics") on first exit — both declared in `story/grants.js`. The story beat that advertises it is `rachel_wardrobe` (`15-the-wardrobe-mirror.dlg`), served by the `rachel-after-karen` trigger 900 ms after Skip's first-loss pep talk, room-guarded to the cubicle farm; it is a pure suggestion — no grants, no gate, and the mirror works whether or not the scene ever plays. The `Down the Hall` side-quest signpost (`_getActiveSideQuests`) clears on first mirror use. **The trigger's event source is `read_karen_first_loss_tutorial`, which needs its existential CODE_GRANTS row**: the closure banks `defeated_karen` for every reachable encounter, which closes the ¬defeated_karen tutorial trigger before its auto-read can land — at runtime the scripted loss forces the order, and the grants.js note carries the full reasoning.
  - **A card's effect line is `stats` THEN `qte`, and an unknown key still prints.** `ergonomic_wrist_support` is `unlock: 'default'` with `stats: {}` — the game's one tradeoff relic lives entirely in `qte` — so a rail that read only `stats` rendered a quarter of the Act-1 wardrobe as a name with nothing under it. `_effectLine()` in `WardrobeState.js` owns this; add a `QTE_LABELS` row when a new modifier lands, and note that the fallback prints `key ×value` rather than dropping it, because the failure it replaces was silent.

Now `_applyFraming` slides the backdrop plane so its `TUBE_FRAC` row lands at 0.62 of the framed half-height (there is no room ABOVE the head — the head top projects at ndc ~0.87 and the glass stops at ~0.86), and each tube runs to its own canvas EDGE so the split lands behind Andrew and cannot be missed at any viewport. **Do not re-tune this by picking pixels; derive it from the same `mid`/`fov` the shot uses.**

It costs no teleport and no room load *because this state owns its scene and builds Andrew procedurally*; that property is the whole reason the menu can reuse it, so do not make this state read the live room. It shipped for one round and was caught by a luminance check reading a model that had nowhere to be, not by eye.

The reflected wall runs a lit tube to the model's LEFT and a dead one to his right, the rig keys from the same side, and the wall texture carries its own falloff **because the backdrop is a `MeshBasicMaterial` and takes no lighting at all** (which is also why turning the rig up barely moves a whole-pane luma reading — measure the MODEL). **The guardrail is the producer's: mood may own the shadow side, the lit side must stay legible enough to judge a hat by.** `tools/_w-mirror.mjs` reads the settled glass off the PNG and requires lit/dark > 1.15× *and* a model-box mean Rec.709 luma > 55; shipping values measure **164.8 / 124.3 and 145.5**. The tube strikes and **settles** in 720 ms and is constant thereafter — it must never strobe while the player is comparing two hats.

Andrew already wears glasses, so without both the equip is a recolour of a ring that was already on his face — measured at the mirror's shipping scale as a change a judge could not see.

### Combat System (`src/combat/`)

- **`CombatEngine`** — Pure logic (no rendering). Key methods: `playerAttack()`, `playerAbility(id)`, `playerItem(id)`, `playerBrace(quality)`, `playerPowerMove()`, `playerPressAdvantage()`, `playerSecondWind()`, `playerRetaliate(multiplier)`, `playerDesperateGamble(risk)`, `playerFlee()`, `enemyTurn()`, `processTurnStart(who)`, `telegraph()`, `getActivePhaseIndex()`.
- **`CombatScene`** — Three.js backdrop; handles enemy/player visual animations.
  - **MATERIAL-SWAP FLASH LAW.** Any effect that swaps a mesh's material and swaps it back (`flashEnemy`) **must capture the original ONCE per mesh and guard the restore with a per-entry token.** Two overlapping flashes otherwise restore each other's *white*: flash B records the white flash A put on the mesh as "the original", and B's restore re-applies it permanently. Measured on a Composure Break (the Break beat fires `enemyHurtAnim` on top of the ability's own hit) as one contiguous white run from **+1150 ms to the end of a 10 s sample** — the boss stayed painted for the rest of the fight. The white material is one shared static, not an allocation per call. Instrument: `tools/_h-flash-probe.mjs` (20 Hz, karen/grandma/chad, PASS = every white run ≤ 200 ms and last sample white 0).
  - **One beat, one clip play.** `enemyHurtAnim`/`allyHurtAnim` call `setExpression('hurt')` *and* `playGesture('hurt')` on consecutive lines, because on the **procedural** rig those mean face and body. On the Meshy cast they were both `play('hurt')`, so every impact fired the clip twice 0–1 ms apart and the second `reset()` restarted the first's 250 ms fade-in from weight 0. `MeshyAnimator.setExpression('hurt')` is now a deliberate no-op. Before adding a new expression→clip mapping there, grep the CombatScene call site for a `playGesture` on the next line.
  - **THE DEFEAT STAYS DOWN.** `enemyDefeatAnim` plays a real gender-paired collapse clip (`CLIP_IDS.defeat`, `m: a58` / `f: a359`) through `playGesture('defeat')`, which is the ONLY caller of `play(role, { stay: true })`. `stay` does two things and both are load-bearing: it keeps the action **out of `_oneShot`**, because the mixer's `finished` listener calls `_toIdle()` on whatever is in there and a defeated body that returns to its breathing stance has stood back up; and it latches **`_down`**, which makes every later `play()` a no-op, because `CombatState` fires several beats in the ~620 ms after the killing blow and any one of them would put the body back on its feet. `clampWhenFinished` (already true on every action) parks the pose on the final frame. **The old beat is gone and must not come back**: it sank the group 2 world units through the floor while spinning it 1.5 rad and shrinking it to 0.5×, which is the vanish producer ruling C3 was about. The procedural cast keeps a topple as the degrade — `playGesture` returns falsy there — but **without the sink and the shrink**. Measured through the shipping victory path (`tools/_fr2-b23-defeat.mjs`): kill→collapse 824–854 ms, collapse 1733/1867 ms, seated hold 1204–1327 ms, stage clears at +3.0–3.1 s. The tool asserts stage height, scale, `_current`, `_down`, that the stage does not clear before the collapse finishes, **and the settled pelvis height** (see the next bullet).
  - **AND IT SITS ON THE FLOOR, WHICH IS A SECOND THING** (`src/combat/MeshyFloorSit.js`). a58 and a359 are **chair** sits — the performer settles onto furniture this stage does not have, which the producer read on sight as "they're sitting on an invisible chair". The B23 sweep could not see it because its metric was *silhouette descent off the vendor's preview GIF*, and a chair sit descends; the clips' own catalog rows say it in a number nobody re-read (`heightRatio_last` 0.9167 for a58, 0.7539 for a359, against 0.2471 for a body actually on the ground). Measured on the real bodies: the settled hips parked at **31–37 % of character height** with both soles still flat on the floor. `fitFloorSit()` keeps sinking the pelvis along the clip's OWN descent curve — a running-minimum normalisation, so it is 0 on every standing frame and full at the settle, with no per-clip time constant — and re-solves both legs with two-bone IK so **the ankles do not move**. That last part is the whole trick: a chair sit translated straight down puts the shins through the floor, because the shins are near-vertical and the feet are already planted. Cast-wide result, `meshy-spine-gate.mjs`: settled pelvis **0.545–0.643 → 0.140–0.264** of the same body's standing pelvis; defeat floor band **−0.0348..0.0441 → −0.0071..0.0624 m**, inside the ±0.01 penetration rule. Three things to know before touching it: (1) **the bend direction is taken against the ORIGINAL hip→ankle line, then re-orthogonalised against the new one** — orthogonalising the raw knee offset against the new line looks equivalent and drives the knee *through the floor* once the pelvis is below the ankle (measured chad kneeL −0.0866 m, min sole −0.222 m); (2) **how far a pelvis can sink is a fact about the MESH, not the skeleton** — karen can reach 8.7 % of height with nothing touching while client_m_heavy's thigh is under the stage at the same number, so `fitFloorSit` PROBES the body (whole-mesh strided sample, not `groundOffset`'s soles-only set, which is blind to a pelvis by construction) and raises the aim only as far as the settled frame demands: fitted 0.138 / 0.204 / 0.288 of bind hip height on karen / chad / client_m_heavy; (3) the model therefore has to reach `clipsFor(id, modelId, targetRest, model)` — **every harness passes it too**, or the gate is measuring a different pose from the fight. A/B switch `globalThis.__floorSitOff` (`--noground` on both tools) reproduces the chair sit; the gate fails 33/33 on it.
  - **`mixer.setTime(clip.duration)` READS FRAME 0.** Under three's default `LoopRepeat` the mixer wraps, so every "sample the clip end" loop in this project — `MeshyRetarget.groundOffset` (14 samples), `meshy-spine-gate`'s `__pose`, and any new sweep — was silently re-reading the FIRST frame as its last sample. Harmless on a clip that returns to its stance, and the reason a **chair sit passed a floor check for a whole round**: the one frame `defeat` is about was the one frame nothing had ever looked at. Always `setLoop(LoopOnce, 1)` + `clampWhenFinished` and ask for `duration − 1e-4`. Fixing it in `groundOffset` only ADDS information (frame 0 is still sampled at s=0), so the measured minimum can only fall and a character can only be **lifted** — measured on chad's defeat, offset 0.0625 → 0.0313, which is exactly the 3.5 cm his right foot was spending under the stage; cast-wide the worst reaction-role floor penetration went **−0.0348 → −0.0079 m**.
- **`EnemyAI`** — Enemy ability selection; patterns: `random`, `escalating`, `aggressive`, `tactical`, `rotation`, `strategic`, `chaotic`.
  - **TWO AGGRESSION DIALS, BOTH INERT UNTIL A ROW AUTHORS THEM, AND THE DIFFERENCE IS A SAFETY ARGUMENT.** `preferAttack` (unconditional; `aggressive` has always had it at 0.7) and **`escalateAfterDenial`** (fires only on a pick made while the enemy is *owed* a turn — `denialStreak > 0` or `sealed`). Both resolve through `_damagingPick`. **No row authors `escalateAfterDenial` today**; the balance proposal that would is dark at `.claude/plans/l-run/PROPOSAL.diff` and needs the producer's signature. The gate is the point: the CASUAL policy denies **0.0 %** of enemy turns on every solo rung (it lands no tagged hit, so it clears no Objection and fills no Composure bar, and it never Braces), so an `escalateAfterDenial` row is unreachable by the PIP floor *by construction*. An **ungated** `preferAttack` is not — authored at 0.55 on Grandma it cost the floor **31.6 pp** at grandma@8 / PIP 20 %. Measure any new row with `node tools/_l-balance.mjs --pip`.
  - **`_escalationPick` runs ABOVE the pattern switch, and that ordering is the mechanic.** It first sat where each pattern would otherwise have drawn at random — i.e. *after* `tactical`'s heal branch and *after* its `debuffChance` branch, both of which return early — so only **50.0 %** of Grandma's owed picks ever reached it and an 0.85 dial delivered about 0.42. Do not "tidy" it back into the branches.
  - **`strategic`'s rotation silently degrades to a uniform random draw.** Its `phase1`/`phase2` lists were authored against an enemy's BASE `abilities` array, and the phase system then replaces that array per HP band, so `abilities.includes(pick)` is false for most of the fight (Meredith's phase-1 list has no `strategic_pivot`; the Director's phase-0 and phase-2 lists have no `market_correction` / `quarterly_target`). Fixing the lists is a content decision nobody has made; `_attackFallback` sits on that fallback so at least the dial can catch it.
  - **`COMBAT_DEPTH.PRESS_ADVANTAGE_BASE` / `_FLOOR`** hold the two numbers `getPressAdvantageCost()` used to inline (40 / 25, cost = `max(FLOOR, BASE − floor((spd − 8) / 2))`). They are a **ceiling-only** knob: `combat-sim.mjs`'s CASUAL policy has no branch that calls Press Advantage, so moving them cannot reach the floor.

**Combat mechanics:**
- **Telegraph**: `telegraph()` pre-rolls the enemy's next ability at the start of each player turn; consumed by `enemyTurn()`. Hint generated in `CombatState._getTelegraphHint()`. If `enemy.vulnerable > 0`, hint appends `(VULNERABLE — hit for 1.5×!)`.
- **Weakness/Resistance**: abilities have a `tag` (`legal`, `social`, `audit`, `technical`). Enemies have `weakness` and `resistance` fields. Weakness = 1.5×; resistance = 0.7×. Applied in `_calcDamage()` only when hitting the enemy.
- **THE PIVOT — a boss's weakness is NOT a fixed property.** Four bosses (chad, grandma, meredith_boss, regional_director) author `weakness` / `resistance` **per phase** in their `phases[]` rows; `CombatEngine._syncPhaseTraits()` resolves the active row onto the LIVE `enemy.weakness` / `.resistance`. It is called from `telegraph()`, `_pickEnemyAbility()`, the player's `processTurnStart` and the top of `_calcDamage`, because the HUD (`COMPOSURE — X ONLY`) and `_getTelegraphHint` read `enemy.weakness` directly and it therefore has to be persistent state, not a per-hit lookup. **Row 0 (the base state) is never changed**, so every documented weakness in `Gameplay.md` and every dialog hint stays true. `karen` and `algorithm` are EXEMPT. Three authoring laws, all measured: (1) the tutorial boss does not pivot; (2) the SOCIAL phase goes LAST, because from L8 `per_my_last_email` at 55 power is the biggest single-target ability in the game and a social phase is therefore a damage *upgrade*; (3) **pivot toward the player's second-best practice area, never their worst** — sending Meredith's phase 1 to `technical` (one ability exists in the whole game) made monotony WORSE, 42.2 % → 56.2 % top-tag, because a player with no button in the new area just keeps hitting the old one off-weakness. Measured effect on a player who never opens the Abilities tab: Grandma's top-tag share 83.6 % → 50.3 %, the Regional Director's 72.7 % → 66.0 %, Meredith's 50.9 % → 41.3 %, at ±1.5 pp of win rate.
- **Vulnerability window**: enemy is `vulnerable = 1` after using Heal or Confuse. The next player hit deals 1.5× and clears the flag. Decrements in `processTurnStart('enemy')` if not consumed. **A Composure Break arms it at `vulnerable = 2`, not 1** — the tick fires on the enemy's own turn-start, which a broken enemy still runs before losing the turn, so at 1 the window closed before the player ever got to swing. Two spends one tick on the skipped turn and leaves exactly one player turn to cash in. Heal/Confuse stay at 1 because they fire *during* the enemy turn. Do not unify the two values.
- **Follow Through combo**: if the enemy has any active debuff (negative stat buff) when the player attacks, damage is ×1.25 and `result.combo = true`.
- **Momentum/Confidence bar** (0–100): gains from hits, crits, weakness hits, combos; loses from big incoming hits and stuns.
  - At `pressAdvantageCost`+: `playerPressAdvantage()` — moderate attack + DEF debuff on enemy. **It does NOT end the turn** (E33 Gradient model) — `CombatState._executePressAdvantage()` calls `_enablePlayerInput()` again, and `player.pressAdvantageUsedThisTurn` caps it at once per turn (reset in `processTurnStart` on the player side). Cost scales with SPD: `max(25, 40 − floor((spd − 8) × 0.5))` — repriced upward because it is now a free action. Use `CombatEngine.getPressAdvantageCost()`; never hardcode. Pass the result as the sixth arg to `CombatHUD.showMainMenu`, and `{ pressAdvantageUsed }` as the eighth, so the button disappears once spent.
  - At 50+: `playerSecondWind()` — restore 25% HP, clear one status, costs 50 momentum.
  - At 100: `playerPowerMove()` ("Assert Dominance") — ignores 75% DEF, resets bar to 0.
  - Base gain is `10 + (crit?10:0) + (super?10:0) + (combo?5:0)` per hit. Momentum does **not** drain from incoming damage or stuns — only from spending moves.
- **Brace** (QTE): `CombatState._showBraceMiniGame()` runs a timed bar mini-game before calling `playerBrace(quality)`. Quality is `'perfect'`/`'good'`/`'miss'` — each gives different DEF bonus and duration. A successful brace halves the next incoming hit and sets `player.retaliateReady = true`.
- **Retaliate** (QTE): `CombatState._showRetaliateQTE()` first shows a length-selection screen (3–6 keys, styled like Desperate Gamble). The chosen length sets a base multiplier (3→0.75×, 4→1.0×, 5→1.25×, 6→1.5×). `_runRetaliateSequence()` then runs the memorize/input loop; final multiplier = `base × (correct/total)`. Calls `playerRetaliate(multiplier)` (22 base power, +15 momentum). Only available when `retaliateReady` is true.
- **Desperate Gamble**: Available when player HP < 25%. `CombatState._showDesperateGamble()` presents a risk menu (`safe`/`risky`/`all_in`). Calls `playerDesperateGamble(risk)`. `all_in` is **40% for 3.0×** (EV 1.20×) and a miss banks **+40 momentum** — it was 30% for 2.5× (EV 0.75×), i.e. strictly worse than Safe Bet with an achievement attached. All three tiers live in `COMBAT_DEPTH` in `CombatEngine.js`.
- **Confuse cooldown**: enemy `confuseCooldown` is set to 3 after using Confuse; `_pickRandom()` and `tactical` pattern skip Confuse while `confuseCooldown > 0`.
- **Confusion semantics** (`_applyConfusion`, replaced `_maybeConfuseActor`): confusion **never replaces the chosen action**. It scrambles the TARGET (50%, multi-enemy fights only) and dampens the action to 65% force (damage *and* healing). The old 50%-chance-you-hit-yourself roll is gone — it was the exact "frustrating death" failure mode Sandfall named. Results carry `confusedScramble` / `confusedDampened`.
- **LOCKS** (Sea of Stars): a telegraphed enemy move can carry 1–2 damage-type locks (`enemy.locks = [{ tag, cleared }]`, built in `telegraph()` via `_buildLocks`). Landing a matching-**tag** hit clears one (`_clearLocks`, called from `_calcDamage` for any tagged hit, plus tagged debuff/silence paths). Full clear → `enemyTurn` returns `{ type: 'fizzle' }` and the enemy's turn is consumed. Partial → the move lands at `1 − 0.30 × cleared`. Which moves carry locks is capped per enemy by `_lockableSet` (a third of the kit, heaviest first, minimum one); tags are hash-stable per ability id so they are learnable. Author overrides: `ENEMY_ABILITIES[id].locks = ['legal','audit']` or `.lockCount`, also via `balance.json`'s new `enemyAbilities` block.
- **`telegraph()` is a promise**: it no longer re-rolls an enemy's pending move. Re-rolling would discard Locks the player already paid tagged hits to clear.
- **COMPOSURE / BREAK** (HSR Toughness): every enemy has `composure`/`maxComposure` (60/90/120 by HP tier via `_defaultMaxComposure`, overridable as `maxComposure` in `ENEMY_STATS`/`balance.json`). Only **weakness-tag** hits reduce it (30 each); a **perfect Brace** strips 20% of max. At zero: `broken = 1` → the enemy loses its next turn (`{ type: 'broken' }`), takes **+20%** damage until it recovers, then Composure refills. While unbroken, incoming damage is **×0.9** — the standing pre-Break tax that makes Breaking read as unlocking your real damage (and the lever that keeps the new agency from just making every fight easier).
- **LOOP IN** (P5R Baton Pass): a weakness hit with a living bench ally sets `engine.loopInReady`. `CombatState._maybeOfferLoopIn()` shows `CombatHUD.showLoopInPrompt`; `engine.playerLoopIn(allyIndex)` runs that ally's turn at ×1.5 damage (`_allyDamageMult`), gives Andrew +10 momentum, and CombatState drops the ally from `_turnQueue`. Once per turn (`player.loopInUsedThisTurn`).
- **Boss phases**: `_pickEnemyAbility()` selects the active phase by finding the phase with the **lowest** `hpThreshold` that is still ≥ current HP%. Phases are listed high→low. `getActivePhaseIndex()` returns the 0-based phase index for `CombatState._checkPhaseChange()`.
- **Henderson phases**: Karen/Chad/Grandma each have 2 additional phases (triggered at 50% and 25% HP) with new abilities and `phaseMessages`. Phase transitions fire a screen effect, a message, and an enemy taunt.
- **Combat taunts**: `ANDREW_TAUNTS` in `stats.js` maps event keys (`crit`, `weakness_hit`, `brace_success`, `power_move`, `enemy_crit`, `retaliate`, `confused`) to quip arrays. Enemy taunts come from `ENEMY_STATS[id].taunts`. `CombatHUD.showTaunt(text, side)` renders them as speech bubbles.

- **PRACTICE GROUPS** (`PRACTICE_GROUPS` + `track` / `depth` on every buyable ability, `stats.js`): the Abilities tab is three career lanes at **nine points each** plus an eight-point shared **General Practice** pool, against **one upgrade point per level-up for life (14)** and **12 more points of ally abilities** buyable from the same pool. **The scarcity IS the design.** If a playtester reports the trees feel impossible to complete, the answer is the free respec (`Request Restructuring`, already shipped, already unlimited) — **do not raise the point supply.** `track` groups the tab; `depth` is the authored SPEND ORDER inside a track and both the tab and `tools/_j-verify.mjs` sort by it. Getting that order wrong is not cosmetic: with Audit's debuff sorted ahead of its first attack, the lane lost **15.3 pp** of win rate on karen@3.
- **PASSIVES ARE ORDINARY `PLAYER_ABILITIES` ROWS** with `type: 'passive'`. That costs zero new persistence — `Player.unlockedAbilities` already stores ids, `MenuState` already renders them and `Request Restructuring` already refunds them. The engine **reads** them (`CombatEngine.nodes`, passed as `nodes: [...player.unlockedAbilities]` from `CombatState`); it never executes them. `playerAbility()` returns `null` for a passive and `_availableAbilities()` filters them out of the action menu.
- **BUILDER TRAP — every buyable node needs an explicit `tier`.** `MenuState._spentUpgradePoints` skips `(a.tier ?? 0) === 0` and `_restructure` resets `unlockedAbilities` to the five starters, so a node with no `tier` field is buyable, wiped by Request Restructuring, and **never refunded**. The player permanently loses the point.
- **THE TIER GATE** (`TIER_LEVEL = { 1: 2, 2: 6, 3: 10 }`, checked in `Player.canUnlockAbility`, greyed in `MenuState._renderAbilities`): minimum character level per tier. It reproduces the shipped pacing for a player following a lane in order and costs the honest lanes one cell. What it stops is the optimal shopper — measured on shipped data, spending the same three points on `cite_precedent` + `per_my_last_email` instead of a lane order HALVES Chad (6.34 rounds → 3.72).
- **OBJECTION SUSTAINED — the One More, ONE mechanism in TWO grades.** A weakness hit sets `engine.turnBackReady`; `CombatState._maybeOfferTurnBack()` banners it and hands input back with a restricted menu. `'sustain'` is universal and free and **may not deal damage** (Brace / items / self-buffs / heals). `'attack'` is **Motion for Summary Judgment**, the Litigation capstone, and is an **UPGRADE of that same return**, once per engagement — never a second proc, never a second prompt, never a second code path. Gates: once per Andrew turn; never off the hit that Broke the bar; never off a hit on an already-Broken target; independent of Loop In; costs no Confidence; **suppressed while more than one enemy is alive** (you cannot move for summary judgment against three parties at once). Two measured laws behind the shape: adding MSJ to `Uc` instead of upgrading it costs 66.8–89.8 % of baseline effective enemy turns, and letting the returned turn spend the **momentum verbs** (Assert Dominance, Retaliate) instead of a basic attack costs **62–74 %** — a returned turn carrying a 75-power DEF-ignoring hit is worth about a quarter of a boss. **The returned turn is a basic attack. Not "any untagged action".**
- **THE CURRENCY GRAPH.** A weakness hit is the sole issuer of four currencies at once — the ×1.5 multiplier, Composure→Break, the Lock clear, Loop In, plus the Confidence bonus and (via the Break) `vulnerable`. Everything else pays one, sometimes two. That, plus `CombatHUD` printing `COMPOSURE — <WEAKNESS> ONLY` off live enemy state every frame, is why weakness play was 72–84 % of tagged hits on the three longest fights: there is no identification cost, and a rational player presses the printed button. Each Practice Group is granted an **exclusive second issuer** of one of those currencies — Litigation turn economy, Compliance Composure off DEFENCE, Audit Composure off OBJECTIONS — and the price of holding it is the other lanes' nodes. **`exposed`, `protected` and player-side DoTs remain wired into the engine and written by nothing.** They are the parts bin; this design deliberately does not spend them.

**Damage formula**: `max(1, floor((atk + power) × 1.5 − def × 0.5 ± rand(3)))`, then weakness/resist multiplier, then vulnerability multiplier, then combo multiplier. Basic attack uses `power = 0`, so damage ≈ the displayed ATK stat. Abilities set their own `power` value.

- **`enemyOverrides`**: `CombatState` accepts an optional fourth constructor argument `enemyOverrides = {}` which is spread over `ENEMY_STATS[id]` after copying, allowing per-fight stat injection without mutating global data. Use this for scripted fights (e.g., one-shot tutorial: `enemyOverrides: { atk: 999 }`). Pass it through `_startCombat()` → `new CombatState(..., enemyOverrides)` → `new CombatEngine(..., enemyOverrides)`.

**`CombatHUD.showMainMenu` signature**: `showMainMenu(silenced, momentum, bracing, retaliateReady, lowHP, pressAdvantageCost = 25, voicesAvailable = [], opts = {})` — pass all eight. **Never call it from inside `CombatHUD` and never call it bare.** There is exactly one caller in the codebase now — grep-verified: `CombatState._showMainMenuLive()`, which reads all eight off the live engine. `CombatHUD.show()` used to end with a bare `this.showMainMenu()`, making the law false; it is deleted. Nothing is lost, because `_enablePlayerInput()` repaints with all eight before input is enabled — but that leaves `.combat-actions` empty for the 1.7 s enemy-intro beat, so `styles/combat.css` carries `.combat-actions:empty { display: none }`. **If you ever see a blank action panel, fix it in CSS or in `_showMainMenuLive()`, never by restoring a bare call.** Every path back to the main menu (first render, submenu Back, target-picker cancel, Escape, "no abilities available") goes through it. The three submenu **Back** rows (`abilities`/`items`/`voices`) raise `onActionSelect('back')` — the HUD does not know engine state, and a bare `showMainMenu()` applied all eight defaults, measured live as **9 buttons collapsing to 4** in one keypress (Press Advantage, Second Wind, Assert Dominance, Retaliate, Desperate Gamble and the Reasonable Doubt voices all vanishing while the Confidence bar still read 100 %) and re-enabling a Silenced Special button. `_handleAction('back')` is a pure UI move: it neither consumes the turn nor drops `inputEnabled`. The sixth argument controls the Press Advantage threshold and button label (get it from `this.engine.getPressAdvantageCost()`); the eighth is `{ pressAdvantageUsed }`, which hides the Press Advantage button once it has been spent this turn (it is a free action now, so the momentum tier alone no longer hides it). Tiered momentum buttons, Retaliate, and Desperate Gamble are injected dynamically based on state. No XP bar in combat HUD — XP progress is only shown in the Stats tab of MenuState.

### World (`src/world/`)

- **`RoomManager`** — Loads rooms from `src/data/rooms/index.js`, instantiates NPCs. NPCs with a `condition` object start **hidden** by default; `EntityManager.update()` shows/hides them each frame based on player flags. This means conditional NPCs never flash visible on room entry.
- **`Room`** — Builds `TileMap`, places `Furniture`, manages exit triggers. `build()` also fills **`room.seats`** — every real seat pad placed this build, in world tiles, with the heading its occupant should adopt (`SEAT_PROPS` at the top of `Room.js`; chair/executiveChair/operatorChair/leatherArmchair/dinerBooth, the last with two benches at local x ±0.61 whose occupants face *across* the table). `StageDirector`'s `sit` beat reads it, which is what makes "sitting on air" structurally impossible for staged sits. **Bar stools are deliberately absent** — their seats are at 0.745 and `CharacterAnimator.SEAT_Y` is 0.44. Furniture entries support an optional `y` property for vertical offset (e.g., `{ type: 'monitor', x: 8, z: 2, y: 0.06 }`) — useful when a custom furniture model has a taller surface than the standard desk height of 0.72.
- **`Furniture`** — All furniture is built as static factory methods on the `Furniture` object (e.g., `Furniture.desk()`, `Furniture.pokerTable()`). `Room._placeFurniture()` does a direct `Furniture[type]` lookup, so a new type only needs: (1) a method in `Furniture.js`, (2) `NO_BLOCK` in `Room.js` if it shouldn't block movement, (3) a `FURNITURE_FOOTPRINTS` entry if wider than ~3 tiles, (4) a `SKIP` entry in `Engine.applyRoomFX` if it must not get a contact-shadow blob. **`Furniture` is a plain object literal — a duplicate key silently overwrites, exactly like `ENEMY_ABILITIES`.** `stairFlight` was defined twice; the numeric full-width version won and the wall version was dead, so `{ type: 'stairFlight', variant: 'up' }` would have called it with `stepCount = 'up'` → NaN geometry. The wall version is now `stairFlightWall`. Grep for a key before adding it.
- **`TileMap`** — Grid-based collision (`canMove()`). Grid values: `0` walkable, `1` blocked, `2` interactable, `3` exit; `isWalkable()` accepts 0/2/3. **`setInteractable()` only claims a tile that is currently `0`** — it must never lower a `1`. `Room.build()` blocks furniture (step 3) *before* registering interactables (step 5), so the old unconditional `set(x, z, 2)` punched a walk-through hole in whatever furniture the interactable was attached to: measured at **29 props across 12 rooms**, including Andrew's desk, five server racks, five HR filing cabinets, the executive `grandDesk`, the vending machine and the player's own car. Nothing reads grid `2` to *find* an interactable — `_getNearbyTargets` goes straight to `interactData` via `getInteractable()`.
- **`IsometricCamera`** — Smooth follow camera with dead zone. `follow(x, z, y)` and `snapTo(x, z, y)` both take an elevation and lerp it at `FOLLOW_SPEED`; **pass the player's `mesh.position.y`, never a hardcoded 0.** With 0 the camera stayed on the ground floor of the game's only multi-level room and the player sank 66 px down a 900 px frame descending the stairwell. Bounds go through `ExplorationState._applyCameraBounds(roomData)`, which caps the inset at half the room — a flat `setBounds(2, w - 2, …)` collapses on anything narrower than 4 tiles (the 4-wide stairwell got `[2, 2]`, pinning camera x permanently).

### Data (`src/data/`)

All game data is plain JS objects/exports:
- `stats.js` — `PLAYER_BASE_STATS` (includes `aum: 0`), `XP_TABLE` (15 levels, exponential), `LEVEL_GROWTH`, `PLAYER_ABILITIES` (with `tag` fields), `ENEMY_STATS` (with `weakness`/`resistance`/`phases`/`phaseMessages`/`taunts` on Hendersons), `ENEMY_ABILITIES`, `ANDREW_TAUNTS`, `ITEMS`, `pickMessage()`. Imports `balance.json` and applies overrides via `Object.assign` at the bottom of the file.
- `shop.js` — `SHOP_ITEMS` (consumables, upgrades, decor, renovation) and `SHOP_CATEGORIES`. Renovations are post-game only (5M AUM each, +2000 XP), except `renovation_penthouse` which costs 10M AUM. Each renovation item has a `flag` that is set on purchase and may trigger visual changes in the target room. Imports `balance.json` and applies shop price overrides.
- `balance.json` — Editor-managed override layer for all tunable values: player base stats, all enemy stats, all ability stats, all shop prices. Written by `npm run editor`. Imported with `with { type: 'json' }` in `stats.js` and `shop.js`.
- `room-overrides.json` — Editor-managed furniture/NPC position overrides. Structure: `{ roomId: { furniture: { "index": { x, z, rotation } }, npcs: { "index": { x, z, facing } } } }`. Applied in `Room.build()` before `_placeFurniture()`.
- `character-overrides.json` — Editor-managed character color overrides. Structure: `{ characterId: { bodyColor: 0xRRGGBB, ... } }`. Applied at the bottom of `characters.js` via `Object.assign` loop.
- `items.js` — Re-exports `ITEMS` from `stats.js` for convenience + exports `STARTING_INVENTORY` (starting loadout: 2× large coffee, 1× antacid).
- `ambience.js` — `ROOM_AMBIENCE`: room id → `{ every: [minSec, maxSec], cues: [[sfxName, weight], …] }`, drained by `ExplorationState._updateAmbience`. The cues are `amb_*` cases in `AudioManager`. **SFX ONLY — NO MUSIC**; music is Alex's domain and his absolute veto, and a beat that wants a sting is a request to him, never a spec. Three rules the scheduler holds and the evidence harness measures: it SKIPS its slot (never queues) while `NotificationArbiter.isActive(NC.VOICE)`, because a cue the player half-hears under a line is worse than a gap; it never plays the same cue twice running; and a room with **no entry is silent on purpose** (`floor_13`). Suppression during dialog/combat/menus is free — `_updateAmbience` only ticks from `ExplorationState.update`, which `paused` already gates.
- `bestiary.js` — `BESTIARY_DATA`: maps every enemy `id` to `{ name, category, quip }`. Displayed in the Journal tab of MenuState. Add an entry here whenever a new enemy is added to `ENEMY_STATS`.

### Dialog authoring (`src/data/dialogs/*.dlg`)

**The `.dlg` files are the source. `index.js` is output.** Edit a `.dlg`, run
`npm run dialogs:build`, commit both. Editing `index.js` turns the build red at
`dialogs:check`, which runs FIRST in `npm run check` for exactly that reason.

The format is line-oriented: **one node per line, no brackets, no commas, no quoting.**
Every prose-bearing line splits at its FIRST colon and everything after it is verbatim —
apostrophes, quotes, colons, dashes, asterisks, arrows. Prose never needs escaping in any
position. A malformed line is ONE diagnostic and every other line in the file still parses;
that non-cascading property is why the format was chosen over JS object literals. The 13
lowercase directives are `ask if goto end set fight give xp stat heal quest recruit teach`;
a speaker name must begin with a capital letter, which is how the two are told apart.
**The one-page grammar card is `tools/dlg/grammar-card.md`. Read it before authoring.**

**EVERY `ask` MUST CARRY AN `@label`, and it is a save-key rule.** `_chose_<dialogId>_<nodeIndex>_<choiceIndex>`
is persisted, and the lock only pins an index that a LABEL claims — so an *unlabelled* choice
node slides whenever a line is inserted above it, silently changing that key for every save in
the wild. Measured on the shipped corpus: one prose line added above `branch_decision`'s `ask`
moved it from index 6 to 8, and the entire reviewable lock diff was `"length": 36 → 37`.
49 of the 61 choice nodes were unpinned; all 61 are pinned now, `npm run check` fails on an
unlabelled `ask`, and adding all 49 labels left `index.js` **byte-identical** because a label
consumes no index. This is the half of the never-insert law the labels-and-`goto` design does
*not* close on its own: jumps became names, but choice indices are still positional.

`dialogs.lock.json` is the **append-only label→index ledger** — *append-only*, not frozen.
`npm run dialogs:build` writes it when the change is purely additive (a new label, a new
scene, a grown length) and prints each addition; `dialogs:check` reports a stale lock exactly
the way it reports a stale `index.js`. A **non-additive** change — a label that would move or
be dropped, a scene that would shrink — is a hard compile error and nothing is written, with
a message naming the label, both indices and the consequence (*"would change the `_chose_`
save keys of every player who has taken a choice in this scene"*). It is what makes the
whole thing safe. A label keeps its index forever; a new label takes the next free index; a
removed label leaves its index RESERVED and the compiler emits an `{ type: 'end' }` pad
into the hole (the padding convention this corpus already used — 41 unreferenced pads
shipped). No index is ever reused. That is not tidiness: `_chose_${dialogId}_${nodeIndex}_${choiceIndex}`
(`DialogState.js:271` reads it, `:310` writes it) is a persisted save key, and the lock is
what keeps it stable — **for every LABELLED index**, which, since the choice-pin rule above,
is every index a save key can name. The lock is committed and its diff is the human-readable
proof that a content change moved no labelled node. Be precise about what that diff shows:
it is *semantically* additive (no label moved, none dropped, no scene shrank), not literally
addition-only — appending a label to a scene rewrites that scene's `labels` object and its
`length`. `--reseed` is refused without `DIALOGS_LOCK_RESEED=i-know` in the environment; it
has been used exactly once.

**Dev loop:** `npm run dev` serves the freshly compiled module in place of the file
(`tools/dlg/vite-plugin-dlg.mjs`, `apply: 'serve'`). Edit a `.dlg`, save, the running game
reloads with the new line. A compile error logs diagnostics and **keeps serving the last
good module** — a typo must not white-screen the game. `vite build` never uses the plugin;
production reads the committed artifact.

Compiler checks that fail the build, beyond the grammar: unknown node type (the corpus
shipped a `{ type: 'Andrew' }` node that never rendered once and nothing ever said so);
unresolved label with nearest-three suggestions; duplicate label in a scene; duplicate scene
id across files; a scene with no reachable `end`; `mode quiz` / `mode evergreen-hub`
disagreeing with `DialogState`'s two `Set` literals in either direction; every `fight` id in
`ENCOUNTERS`, every `give` in `ITEMS`, every `stat` in `PLAYER_BASE_STATS`; every stage beat
actor and mark resolving. Nodes with no path from index 0 are **warnings**, not errors —
there are 42 and 41 of them are the intentional pads.

### The story graph (`src/data/story/graph.js`)

Four blocks, all plain data, all expressed in one array-shaped expression language
(`'flag'`, `['not',X]`, `['all',…]`, `['any',…]`, `['room',id]`, `['set','RENOVATION_FLAGS']`,
`['pred',name]`, and for routes also `['npc',…]`, `['npcDialogId',…]`, `['dialogExists',…]`,
`['act','>=',n]`).

- **`ACTS`** — 7 rows. Highest satisfied index wins. This is one list now, where
  `_syncActFromFlags` and the `questId` ladder used to be two hand-kept parallel ones.
- **`DERIVE`** — 13 rows, 8 `latch` and 5 `live`. **ORDER IS BEHAVIOUR: this is ONE ORDERED
  PASS, NOT A FIXPOINT.** `intern_at_desk` is rule 5 and reads `board_meeting_closed`, which
  is rule 13, so within a single call the Intern flags deliberately lag one call behind;
  rules 6–9 read the value rule 5 just wrote, which is intra-pass. Both are reproduced from
  the shipping code and both are load-bearing. Do not "fix" this to converge. (The
  simulator's closure IS a fixpoint — that is a different tool with a different job, and its
  header says so.)
- **`GATES`** — 9 flag rows (the old `gatedRooms` table) plus 4 declaration-only rows: the
  `archive` and `vault` knowledge gates and the two special conditionals. Those four are
  DATA ONLY; `_changeRoom` still owns them as explicit conditionals that `return` before the
  table lookup, which is why a flag row for either would be unreachable.
- **`TRIGGERS`** — 30 rows, one per code-side scene push, each with its `file:line`. `once`
  is `'scene'` (22), `'always'` (8) or `'flag:<name>'` (0, and a `flag:` row now REQUIRES a
  waiver the simulator prints). See the one-shot law below.

Every rule carries a `note` that says WHY it exists, not what it does. Several of those
notes are the only surviving record of a bug that cost a round — keep them when you edit.

### The story simulator (`tools/story-sim.mjs`)

Pure Node, ~3 s, joins `npm run check`. **A broken story chain is now a red build rather than
a thing you find by playing.** Seven checks:

| | |
|---|---|
| **A** | every `ACTS[].when` flag is in the closure from a fresh save |
| **B** | every flag READ anywhere is in the closure, in `CODE_GRANTS`, or has a `NEVER_SET` reason |
| **C** | every scene in the corpus is routed, triggered, or carries a `SCENE_DISPOSITION` row |
| **D** | every gate flag is reachable from a fresh save — which also covers the circular case, since a key only obtainable behind its own door can never enter the closure |
| **E** | no spend-before-grant: every trigger is `scene`, `always`, or a named waiver — **and** a fight-bearing `once:'scene'` trigger whose encounter has no player-initiable route must declare `reArmOnDefeat` |
| **F** | the expiry check — a grant behind `¬f` must be orderable before `f` |
| **G** | route shadowing: every route row has a satisfying assignment where no earlier row fires |

`--selftest` mutates the model seven ways and asserts each check goes RED, plus an eighth row
labelled REGRESSION #1: the pre-fix `act5_triggered` persisted latch, caught by E and by A
from the interrupted start state. **A gate that has never been seen to fail is not a gate.**

**Check G is a SAT problem — do not branch it in a fixed variable order.** The terminal
`act-ladder` row has 64 earlier compatible rules and 151 atoms between them; a fixed order is
a 2^151 search and the tool ran over ten minutes without finishing, inside `npm run check`.
It branches only on an atom of a currently-undecided constraint, and a decision budget
reports COULD NOT DECIDE as a **failure**, never as a silent pass. Two modelling rules go
with it: `dialogExists` and `act` operands are **not flags** (harvesting them as flags gave
40+ phantom check-B findings — scene ids and the literals `>=`, `==`, `<`), and
`dialogExists`, `act` and `npcDialogId` are **concrete, not free variables** (the corpus is
fixed, act is enumerated 0–7, `npcDialogId` over every literal in the table; pinning it to
null falsely called three Janitor rows shadowed).

**A READ FLAG IS MONOTONE, AND A LOST FIGHT IS NOT A FINISHED SCENE.** `read_<sceneId>` is
written when the dialog ENDS — which for a scene whose last action is `fight` is *before*
the fight is entered — and nothing clears it. That is right for an interrupted scene and
wrong for a lost one. **Three** trigger scenes — the Act-5 gauntlet — start an encounter with
**no player-initiable route anywhere in `rooms/index.js`**, no NPC and no interactable, and
between them they are the sole writers of `corporate_lawyer_defeated`, `data_lead_defeated`
and `board_room_accessible`, so one defeat would have taken Acts 5, 6 and 7 with it. A
fourth row, The Firm's ambush, carries the same declaration as **belt-and-braces**: it does
have a route (the `old_vault` `firm_partner` NPC serves `the_firm_retry`, live in exactly the
post-defeat state), and re-arming it only means the lost fight is re-offered where it
happened rather than only at the partner. Those rows declare **`reArmOnDefeat: true`**, and
`_reconcileSceneLatches` clears `read_<scene>` at LOAD and on DEFEAT unless **every** grant
has landed — `every` and not `some`, because `some` fails toward the soft-lock and `every`
fails toward a duplicate scene. **Check E fails the build if a fight-bearing
`once: 'scene'` trigger with grants has neither `reArmOnDefeat` nor a player-initiable
fallback**, so the next one cannot be authored silently. `tools/_dr-latch-interrupt.mjs`
carries the matching leg: lose the fight, assert the scene IS re-served.

**The honest limits, which the tool prints in its own footer:** monotone closure does not
model resource ordering (AUM prices, level gates), and it does not model **combat outcome**
— the closure banks `defeated_<id>` *and* `retry_<id>` for every reachable encounter, so
"X becomes unreachable after a defeat" is invisible to A–G apart from the one shape check E
now tests by hand. If you are hunting a progression bug that only appears after a loss, the
simulator will not find it for you.

**One more thing `npm run check` does not do:** it does not notice a *content* change. A
`.dlg` prose edit passes `dialogs:check` (which only proves the artifact matches the source),
`story:sim` and `validate:data`. That is deliberate — editing prose is what authoring IS —
and it means the review artifact for a content change is the `.dlg` diff itself.
`node tools/_g-stage-verify.mjs` is the tool that catches an *unintended* one, and it is not
wired into `check`; run it by hand when a change was supposed to be structural only.

### Arcade (`src/arcade/`)

**SPRINT REVIEW** — the break-room cabinet. A Genesis-Sonic momentum platformer wearing an office. Launched from the `arcade_intro` dialog, which sets `launch_arcade`; `ExplorationState`'s `flag-set` listener dynamically imports `ArcadeState` and hides the exploration HUD for the duration.

- **`constants.js`** — every movement number is a **direct conversion of the Genesis Sonic constants** out of px/frame @60fps at a world scale of 20 px = 1 unit (`px/frame × 3` for velocity, `px/frame² × 180` for acceleration). Do **not** re-tune these by feel — the whole point is that the momentum is honest. The fun knobs are the level generator and the props. Also holds `COSMETIC_MILESTONES`, whose **flag keys are load-bearing** (`arcade_gold_wheels`, `arcade_fancy_roof`, `arcade_armored`, `arcade_fire_horses`): MenuState's NG+ `CARRY_PREFIXES` carries anything `arcade_`, and old saves are read through these keys. Labels changed with the rebuild; keys did not.
- **`Terrain.js`** — infinite C1-continuous heightfield built from parametric segments (`flat`/`hill`/`valley`/`slope`/`ramp`/`gap`). Every shape has **zero derivative at both ends** so the slope factor never jumps — except `ramp`, whose steep end *is* the launch lip. `heightAt(x)` returns `null` over a gap. The generator also emits prop-placement requests into `pending`, drained by ArcadeState. Hill/valley profiles are **asymmetric** (gentle rise, hard drop) and amplitude is capped at `0.145 × length`: Genesis' own `ACC 0.046875` vs `SLOPE 0.125` ratio means any sustained slope past ~22° cannot be climbed from a standstill, so a symmetric hill steep enough to be fun to descend is a hill that traps you. Shallow faces land at ~18°, steep faces at ~37°. `TerrainRibbon` is one dynamic `BufferGeometry` (300 columns × **6 rows**) re-sampled at the camera each frame — the row Y offsets matter as much as the colours, because vertex colours interpolate between rows and a bottom row 22 units down smears the subfloor tone across half the screen.
- **`Runner.js`** — Andrew plus the integrator. Grounded state is a scalar `gsp` along the tangent with the Genesis slope factor; **airborne detection is a ballistic test** (step one substep tangentially, then check whether the free-fall path clears the floor) — that single test is why crests launch you. Landing keeps `vx` outright below 0.4 rad and projects onto the tangent above it. Rolling swaps the friction/slope table. Jump fires **along the surface normal**. Spindash follows `gsp = 8 + floor(charge)/2` px/frame.
- **`Props.js`** — office detritus in Genesis roles (filing box/rolling chair = smashable badnik, binder tower/water cooler = hard block, ceiling pipe = low ceiling you must be *rolling* to clear, coffee puddle = momentum tax, paperclip = ring, gym ball = red spring, priority-lane decal = boost pad, checkpoint desk = lamppost). Geometry and materials are created once and shared; only `Mesh`/`Group` wrappers churn.
- **`Backdrop.js`** (3 parallax layers; content authored two spans wide so the wrap never leaves a hole, every layer authored **floor-relative and glued to the camera in Y**, and **no layer may have a visible bottom edge** — a spring launch drops the ground away and exposes one), **`Hud.js`** (DOM + its own injected `<style>`, all `sr-` prefixed), **`Sfx.js`** (chiptune synthesised through `AudioManager.sfxGain`, so mute/volume apply).

**Gotchas:**
- `ArcadeState.enter()` calls `Engine.setTiltShift(false)` and `Engine.setRetroPass(true)`, restoring both in `exit()`. Tilt-shift blurs the top and bottom thirds of an orthographic frame — correct for a diorama, fatal for a runner whose obstacles arrive at the frame edge.
- Physics runs at a **fixed 1/120 substep** with an accumulator; `jumpPressed` is an edge event and is consumed after the first substep.
- `arcade_best_distance` stores **FLOORS** (world units ÷ 25), not raw units, and the permanent +ATK/+DEF ladder is `floors/40` capped at 5. Only newly crossed tiers pay out.
- The `flag-set` listener that launches it **must** test `key === 'launch_arcade' && value`. The handler's own `setFlag(..., false)` re-emits the same key, and without the guard a second ArcadeState is pushed on top of the first — two scenes fighting over `Engine.renderScene`, two HUDs in the DOM, and a title card that cannot be dismissed because the instance holding the keyboard is the other one. This was a live bug in the shipped Stagecoach build.
- `?dev&arcade=1` boots straight into it through that real flag path. `tools/arcade-play.mjs` drives a full session with real key events and writes `run.json` + a video; `window.__arcade` is exposed under `DEV_MODE` for it. **Playwright's `keyboard.press()` with no delay is invisible to `InputManager`** (it diffs key state between frames, and a same-task down+up never shows as pressed) — hold every tap for several frames, and ~220 ms when video recording is on.
- `styles/arcade.css` is the **old** minigame's stylesheet and is now unused (the HUD injects its own CSS). It is still linked from `index.html`; harmless, safe to delete when someone owns that file.

### Effects (`src/effects/`)

- **`Engine.applyRoomFX` FIXTURE PROFILES** — the Severance top-light rig (emissive ceiling troffer + anchored floor pool + light-shaft + specular streak) used to be gated on one derived boolean, `dirIntensity >= 0.9`, which reached exactly FOUR rooms; everything else got a grid of **sourceless** radial pools or nothing. ### Notifications (`src/core/NotificationArbiter.js`)

**One queue owns every transient text surface in the game.** Before it, there were fourteen independent emitters and no arbiter of any kind — nine of them appended a brand-new DOM node per call at a *hard-coded* position, so N simultaneous events rendered N boxes on the same pixels. Measured: **nine achievement toasts at 100 % mutual overlap** (eight never seen), the autosave toast sitting on the post-fight dialog for 6151 ms, and a toast that lived **234 ms of its intended 2600 ms** because combat entry hid the HUD while its own `setTimeout` still ran. Full evidence: `.claude/plans/i-run/notification-audit.md`.

**Post, never build.** `NotificationArbiter.post({ cls, text, zone?, ttl?, key?, tone?, speaker? })`, plus `speak(name, text)` and `monologue(text)` for the prose zone. **Never create a floating text element by hand** — that is the bug this file exists to make impossible.

**The claim ladder** (`NC.*`, highest claim first). The principle: *the player's eyes are a single resource, and the game must never spend them on bookkeeping while a character is talking.*

| class | surfaces | zone | defers while | coalesces |
|---|---|---|---|---|
| `VOICE` | inner monologue, speech cards, combat taunts; the dialog box **holds** it | `voice-centre`, `taunt-left/right` | another **prose** surface is up | no |
| `DECISION` | telegraph, Loop-In, QTE overlays (these **hold**, they do not post) | — | never | no |
| `CONSEQUENCE` | combat messages (floating damage is EXEMPT — see below) | `plate-centre` | never | no |
| `PROGRESS` | objective updates, items, AUM, XP, level-up | `rail-right` | `VOICE` | by key |
| `COMMENDATION` | achievements | `rail-bottom-right` | `VOICE`, `DECISION` | **yes** — "Achievement ×3" |
| `BOOKKEEPING` | "Game saved.", `[DEV]` | `strip-bottom-left` | `VOICE` | yes |

**Four laws, all load-bearing:**

1. **One visible item per zone.** A second post to an occupied zone *queues*; `_render` clears the zone before appending, so double-occupancy is structural, not conventional. This alone retires achievement stacking, double combat plates and double taunts.
2. **Reading-time TTL.** `400 ms + words × 200` (~300 wpm), clamped **per class** — `CONSEQUENCE` 1000–2800 (a combat beat is glanceable and repeats), `VOICE` 2400–9000 (it is prose). An explicit `ttl` still wins. A zone with a backlog drains at ×0.62 so a queue never reads as input lag.
3. **PROSE HAS A CADENCE (B2).** `PROSE_ZONES` is exempt from the backlog `hurry` multiplier and holds its own zone shut for `PROSE_GAP_MS` (1100) after each retire. A first visit to a room in a new act fires the first-visit lines AND the act lines, and the arbiter used to drain that backlog at 0.62× with only its 500 ms fade between cards — one card every ~2.0 s, which is the playtester's "dialogue every 2 seconds". `ExplorationState` also SKIPS the act band on the entry that spends the first-visit latch (the act latch is only spent when a line fires, so nothing is lost). Measured on the same four lines, before → after: blank screen between cards **none at all → 602-643 ms**; middle-card life **1989 → 2899 ms**; card-to-card period **1989 → 3526 ms**.
4. **DEFER, DON'T DESTROY.** `suspendScope('world')` (combat entry) puts the visible item **back in the queue with its remaining ttl**; `resumeScope` re-shows it. `closeScope('combat')` (combat exit) drops pending items *to the Log* — and every later post into a closed scope is logged and dropped, which is the one-line sink-side fix for ~60 orphaned `setTimeout(() => hud.showMessage(...))` calls in `CombatState` that used to paint onto the exploration screen.
5. **Everything is in the Log.** Ring buffer of 40, surfaced as the **Log** tab in `MenuState`. Deferral is only safe because nothing is unrecoverable.

**Gotchas:**
- **The arbiter root is page-level, not inside `.exploration-hud`.** `CombatState.enter()` hides that element wholesale and the combat zones must stay alive. Scope gating — not DOM nesting — keeps world notifications off the fight screen.
- **`_showToast` classifies by CONTENT** (`ExplorationState._classifyToast`). `Name: "…"` or ≥18 words ⇒ `VOICE`, because those are *scenes* wearing a notification. This is why the 61 call sites did not have to change and why a 27-word Diane line no longer runs at 96 ms/word in a corner box. Pass `{ cls: NC.X }` as the 4th arg to force a class (`_autoSave` does).
- **Cards keep the game's existing surface classes** (`.hud-toast`, `.combat-message`, `.combat-taunt`, `.inner-monologue`) and the **zone owns position**. `.na-card` resets the old absolute anchors with `!important`. Keeping the class names is deliberate: every external selector, including `tools/_i-notify-probe.mjs`, still sees the surfaces it was written to measure.
- **Combat taunts are `VOICE` but exempt from prose exclusivity** (`PROSE_ZONES` holds only `voice-centre`). They are character barks tied to a body on opposite sides of the frame; the audit measured `taunt-left × taunt-right` at 0 % overlap. Serialising them would make the fight feel laggy for no gain. Single-occupancy **per side** is what fixes the measured 100 % same-side double-exposure.
- **Three surfaces are EXEMPT by ruling, not by oversight.** `FloatingText` (see its entry below), `CombatHUD.showBanner` (the audit's own cited "one correct implementation" — it already removes the previous banner before appending) and `CombatHUD.showEnemyIntro` (one per fight by definition). All three are `_closed`-latched with the rest of the combat HUD so none can paint after the fight ends.
- **A full-screen surface must `suspendScope('world')`.** The arbiter root is page-level, so hiding `.exploration-hud` no longer hides notifications. `CombatState`, `MenuState`, `ShopState`, `DayState`, `ClientReviewState`, `EpilogueState`, `ArcadeState` and `ElevatorRide` all do. Missing one is not a race — deferral *aims* the card at it: `algorithm_defeated` is set inside the ending dialog, so the achievement defers behind that VOICE hold, releases on `dialog-end`, and lands 900 ms before `EpilogueState` is pushed. Suspension is reference-counted, so nesting is safe.
- **`post({ jump: true })` takes the slot NOW** — evicts the occupant and clears the pending queue. Reserved for the one line that ENDS a scene (the fight's victory/defeat announcement). Without it, "Your patience has run out..." queued behind a backed-up plate zone and was discarded 2500 ms later by `closeScope('combat')` — the player lost the line that says why they lost.
- **`dismiss(id)` is the ONE exception to law 3, and it has ONE caller.** `post()` returns an id; `dismiss()` drops that post instantly — off screen if showing, out of the queue if waiting — and still logs it, as `ended with the room`. The caller is `ExplorationState._dropRoomThoughts`, run from the top of `_loadRoom`. Reason: **a room thought outlives the room.** The room-scoped feed (`_queueRoomThoughts`) only ever owned the lines it had NOT posted yet; a card already on screen keeps a 2.4–9 s VOICE ttl and a door takes under one, so it finishes under the NEXT room's location badge — measured on the wardrobe flow capture as the cubicle farm's desk-plant line still up **4.8 s into the Bathroom**. The queue-side drop cannot catch it, because `_loadRoom` overwrites `_thoughtFeed` with the new room's lines in the same tick, which is why the drop is a separate call placed before it. Do not reach for `dismiss` as a general "close that toast" verb: deferral, not destruction, is the rule, and this is narrow — the player has physically left the subject.
- **NEVER build a second, idle element that carries a surface's class.** `_createHUD` used to append an empty `.inner-monologue` div, left over from before the arbiter owned that surface. It rendered nothing and cost nothing — except that it sits EARLIER in the DOM than the arbiter root, so `document.querySelector('.inner-monologue')` (the selector this file tells every probe to use, and the one `tools/_i-notify-probe.mjs` was written against) always returned the decoy. Measured: the arbiter's own log said `shown` for a line a harness reported missing, and a cross-room-thought assertion passed *because it could not see any thought at all*. If a probe and `NotificationArbiter.getLog()` disagree, believe the log and go looking for a decoy.

### UI (`src/ui/`)

All UI is DOM-based HTML/CSS overlaid on the canvas:
- **`CombatHUD`** — `showMainMenu(silenced, momentum, bracing, retaliateReady, lowHP, pressAdvantageCost, voicesAvailable, opts)`. `updateLocksAll(locksPerEnemy)` renders the OBJECTIONS chip row (skips the rewrite when the row is unchanged so a `shatter` animation survives a `_refreshHUD`); `pulseLockCleared(idx, tag)` fires the shatter beat. `updateComposureAll(enemies)` renders the per-enemy Composure bar; `pulseComposureBreak(idx)` fires the break flash. `updateFindingsAll(findingsPerEnemy)` renders the **FINDINGS chip row** (the Audit lane's previously invisible economy): bright pips are the standing file, the dimmed `ON RECORD ×N` is the monotonic `_findingsEver` record, and the `ATK −N%` suffix is the Hard documentation shield — printed only when `slowPct > 0`, i.e. only where a mode's `audit.assaultSlow` is live. Fed from `CombatState._refreshDepthHUD()` off `CombatEngine.getFindings(i)`, which returns **null for any build without the `findings` node — that null is the entire gate**, and a non-Audit HUD is pixel-identical to before by construction (proven byte-identical on a seeded-RNG frozen capture: `tools/_hud-findings-shoot.mjs --mode=invariance/--mode=diff`). Three laws it carries: (1) **beats are a DELTA, not a threaded result field** — `_findings` only ever moves at a file or a close, so count-up pulses the new pip(s) and count-down fires the row's close flash, which covers ally filings, Management Letter's double-file and Scope Expansion's debuff rider with zero engine plumbing; (2) same skip-rewrite-when-unchanged signature as the locks row, so a pulse survives the `_refreshHUD` that follows every beat; (3) the close announcement is `FILE CLOSED — 30 Composure.` on the existing CONSEQUENCE `showMessage` channel and deliberately does NOT claim the 1.5× — the debuff-rider close (`_fileFinding` at max) carries no damage to multiply, and the message must be true on both close paths. The row stays visible under NDA / Summary Briefing on purpose: those seal the ENEMY's intent, and the file is Andrew's own paperwork. `getFindings` also returns `ever`/`slowPct` using the same arithmetic as the `enemyTurn` shield site, so the HUD prints what the engine does rather than a re-derivation that can drift. `showLoopInPrompt(candidates, onPick, onDecline)` is the baton-pass overlay. Renders Brace, Retaliate (when ready), Desperate Gamble (when lowHP), tiered momentum buttons (25/50/100), telegraph row, and Confidence bar. `updateTelegraph(hint)` sets the enemy intent text. `showTaunt(text, side)` renders speech bubbles on `'player'` or `'enemy'` side. `updateBuffStatus(playerBuffs, enemyBuffs)` renders colored pill badges below the stat bars — call from `CombatState._enablePlayerInput()` and `_updateHUD()`. Duration displayed as `b.duration + 1` (a buff at `duration: 2` has 3 turns left).
- **`DialogBox`** — `onAdvance` / `onChoice` callbacks; `skipToEnd()` / `isComplete()`. Space blocked on choice nodes (only Enter/click). Choice buttons ignore mouse clicks for `CHOICE_ARM_MS` (260 ms) after they render: the box's own click handler skips the typewriter, which paints the buttons **under a stationary pointer**, `mouseenter` moves the cursor onto whichever one landed there, and the second half of a double-click used to commit a choice the player never read. The keyboard path was already guarded (skip first, confirm second); this gives the mouse the same beat. **Any Playwright harness that clicks a choice must wait the 260 ms out first** — a click inside the window is silently *dropped*, not queued, so the row stays up and the next Enter confirms the cursor's default row (index 0) instead. That is a test that answers the *wrong* option while asserting it answered correctly: it cost a full debug cycle in `tools/_a3-board.mjs`, where index 0 of a Janitor riddle is the right answer and the "a wrong answer sets no done-flag" check silently inverted. Same family as the arcade's `keyboard.press()` trap below. **Portrait + speaker-colour wiring is keyed on the exact `speaker` STRING in `src/data/dialogs`, not on the NPC id and not on the `name` in `characters.js`.** `PORTRAIT_KEYS[speaker]` gives a file stem; `src/assets/portraits/<stem>.png` (and `<stem>_<mood>.png`) are picked up by `import.meta.glob` automatically, so dropping art in is enough *only if a row already points at it*. This is a silent failure mode with real cost: `PORTRAIT_KEYS` said `'Alex'` while all 211 of Alex from IT's lines say `'Alex from IT'`, so his four shipped portraits never rendered once, and `delia` had no row at all. Two guards now exist — `validatePortraits()` in `scripts/validate-data.mjs` (part of `npm run check`) **fails the build** when a PNG on disk is unreachable from any live speaker string, and a `DEV_MODE`-only `console.warn` in DialogBox lists orphan stems. When adding a portrait, grep the speaker string out of the dialog data first. **The corollary: a speaker STRING is a UI identity, so changing one is a two-table edit.** `janitor_the_name` node 2 speaks as `'Curtis Briggs'` — the one line in the game where the label corrects itself on the beat the character does — and that required a row in `SPEAKER_COLORS` *and* a row in `PORTRAIT_KEYS`, both pointing at the Janitor's existing colour and existing `janitor` stem. Miss either and the failure is silent in a different way (default grey label / no portrait). He is `'Mysterious Janitor'` in every other scene, because that is what the room calls him.
- **`NewGameScreen`** — the New Game difficulty slider: a Display Case diorama of Andrew at his desk that redresses itself per stop (its own scene, rendered via `Engine.renderScene` + `skipDefaultRender` from `TitleState.update`). CSS is the `.ng-*` block at the end of `styles/menu.css`. Full laws and traps in the dedicated bullet under "Difficulty modes" above.
- **`TransitionOverlay`** — `fadeOut/fadeIn`, `wipeDownOut/wipeDownIn` (descend), `wipeUpOut/wipeUpIn` (ascend).
- **`TouchControls`** — Injects into `InputManager.keys`; activates only on touch devices.
- **There is no `UIManager`.** It was 243 lines of dead code — zero imports, zero instantiations, and its `.hud-notification` toast never rendered once in the shipping game — while this file documented it as the "Master exploration HUD controller" and its `notify()` as the toast API. Both were wrong and it has been deleted. **`ExplorationState._createHUD()` builds the exploration HUD** (location badge, mini-stats, day chip, quest tracker, upgrade tooltip, interact prompt, portfolio panel) and **`ExplorationState._showToast()` is the real toast**, with 61 call sites.
- **`FloatingText`** — DOM-based floating damage/heal numbers. `spawn(text, x, y, type)` where `type` is `'damage'`, `'heal'`, etc. `spawnAt3DPosition(text, worldPos, camera, renderer, type)` projects a 3D world position to screen coordinates automatically. **Deliberately EXEMPT from the NotificationArbiter queue** — the audit measured it at 0 % overlap against every other surface and ruled it acceptable: it is short, spatial and anchored to a body on screen, so serialising it would destroy the read it exists to give. It is capped at `MAX_LIVE` concurrent nodes (the one thing that was genuinely unbounded).

## Key Patterns

- **State lifecycle**: `enter()` sets up DOM/scene; `exit()` tears it down (remove DOM elements, dispose Three.js geometries/materials, remove event listeners).
- **Combat result flow**: `onEnd(result)` returns `'victory'`, `'defeat'`, or `'flee'`. On story victory: `defeated_<encounterId>` flag is set automatically by `ExplorationState`, `bestiary_<encounterId>` flag is set, HP/MP restored to max, then `encounter.postDialogId` dialog auto-plays if defined. On defeat: `retry_<encounterId>` flag is set; the next encounter routes to a `<encounterId>_retry` dialog. `ending_started` is reset on defeat so the executive floor boss re-triggers. `_handleDefeat(encounterId)` also calls `_offerPIP(encounterId)`, which surfaces the free Performance Improvement Plan (the casual assist, `src/data/review.js`) as a toast — once per story boss, keyed on `pip_notice_<encounterId>`, suppressed on `reception_client`, on the scripted first-Karen loss (which returns before `_handleDefeat`), and once `rp_pip` is owned. **Flag naming gotcha**: `defeated_<encounterId>` (e.g., `defeated_regional`) is the auto-set combat victory flag. Post-dialogs sometimes also set a *differently named* flag via a `set_flag` action (e.g., `regional_director_defeated` in the penthouse chain dialog). These are distinct flags — always verify which one ExplorationState's event listeners use before writing NPC conditions.
- **Encounter config**: defined in `encounters/index.js`. Each entry has `enemyId`, `preDialogId` (dialog with `start_combat` action node that triggers the fight), `postDialogId` (auto-played after victory), and `canFlee`. The `start_combat` action in a dialog emits `start-combat` on EventBus; ExplorationState queues it via `_pendingCombat` and fires after `dialog-end`.
- **NEVER GUARD A CODE-PUSHED SCENE WITH A PERSISTED LATCH.** Every code-side story push in
  `ExplorationState.js` used to have the shape `setFlag(started)` then
  `setTimeout(() => push(dialog), 800…2000)`, and the game **auto-saves inside that window**
  (`_changeRoom` ends with `_autoSave`; `_handleDefeat` calls it synchronously). A quit, a
  crash, a closed tab or a defeat therefore banked *this scene has happened* for a scene that
  never ran — and none of these enemies has an NPC entry anywhere in the game, so nothing
  else could ever push that dialog again. **`act4_complete` has ONE setter in the whole game**
  (`act5_trigger` node 8) and `act5_trigger` had ONE pusher; measured 2026-08-15 with
  `tools/_r-act5latch.mjs`, an interrupted entry left `act5_triggered:true /
  act4_complete:false` on disk and walking out of the cubicle farm and back never recovered
  it — **Acts 5, 6 and 7 unreachable** while the world still let the player everywhere they
  had already been.
  **The once-guard is now the scene's own `read_<sceneId>`**, declared as `once: 'scene'` on
  the trigger's `TRIGGERS` row. `DialogState._endDialog` writes that flag only after a node
  has actually been SHOWN (`DialogState.js:575-576`, guarded by `shownAnyNode`), so an interrupted scene is re-servable
  by construction and this bug cannot be authored again. All 19 waived triggers were
  converted; the started flags are all still **written** (saves carry them and they read as a
  record) and none of them is **read** as a guard. `once: 'flag:<name>'` still exists and
  still works, but it **requires a `waiver` string** and the simulator's check E prints every
  waiver by name on every run, so the count can only go down. It is 0.
  `UNFINISHED_SCENE_LATCHES` is now DERIVED from `TRIGGERS` and evaluates empty;
  `LEGACY_SCENE_LATCHES` is the frozen, explicitly-closed seven-row table for saves written
  before the change, and `_reconcileSceneLatches()` keeps running over it at LOAD and on
  defeat. **Do not add a row to the legacy table.**
  Two mechanics keep the delay window honest and both were earned by a measured defect:
  a **session claim** reserves the scene between the decision and the push and is RELEASED on
  every path that abandons the push (plus cleared wholesale in `_handleDefeat`) — never
  released, it becomes exactly the persisted latch this all exists to delete; and the
  deferred push **re-checks the trigger's `when`, `room` and `flag`**, not just the
  once-guard, because a load or a defeat dump can wipe the precondition inside the window.
  Gates: `tools/_dr-latch-interrupt.mjs` (arms each trigger, interrupts inside its window by
  reloading, asserts the scene is re-served, plays it out, asserts no third serve) and
  `tools/_r-act5latch.mjs` legs A/B/C. A/B switch `window.__sceneLatchLegacy`
  (`tools/_r-act5latch.mjs --pre`) restores the shipped guard so the gate can be shown failing.
  **A fixture that skips a scene must set that scene's `read_` flag** — the same law as the
  CAPTURE LAW one level up, and the thing that made two harnesses look like game defects.
- **THE QUEST-STAGE BAND IS A SILENT SWAP, AND `_pendingDialog` BYPASSES IT.** `_getValidNpcDialogId` substitutes `neutral_<id>` / `neutral_npc` whenever `isDialogValidForQuestStage` rejects the routed dialog, so an out-of-band route does not error — the character just says a placeholder line forever. Two consequences, both shipped and both fixed: (1) the generic act rows in `_getDialogId` were `act >= N && DIALOGS[<id>_actN]` while `dialogGating` caps an `_actN` dialog at quest stage N00–N99, so `act >= 3 && !read_alex_it_act3` kept returning a stale `alex_it_act3` at acts 4–7 and Alex answered *"Not a great time. Something is blinking that should not be blinking"* for the rest of the game with `alex_it_return` unreachable — the rows now go through `actRow(n)`, which band-checks, so a stale act dialog falls THROUGH to `<id>_return`; (2) `_pendingDialog` pushes its target **raw**, with no neutral swap, so the `alex_main_chosen` listener's table (which falls through the **non-existent `alex_it_act4`** to `alex_it_act3`) pushed an out-of-band dialog at act 4/5 — every node failed `_isNodeValidForQuestStage` and the skip walk followed `alex_it_act3`'s appended catch-up tail `19→20→21→22→23→19` forever: **`Maximum call stack size exceeded` inside `DialogState.enter()`**, thrown *after* `GameStateManager.push` had already paused the world, leaving a blank input-dead box no key could close. Both halves are fixed and **both must stay**: the listener band-checks, and `DialogState._processNode`'s skip branch carries a `_skipSeen` visited set that ends the dialog on a closed loop. Gate: `tools/_r-alex.mjs` (8 legs fail on `0c0253f`, all pass after).
- **`_getDialogId(npc, commit)` — A QUERY MUST NOT MUTATE.** `update()` calls `_getNpcDialogId(nearNPC)` **every frame** to label the interact prompt, and the router consumes three one-shot flags (`alex_story_chosen`, `alex_story_deferred`, `alex_side_deferred`). So the prompt updater ate the deferral one frame after the router closed and both routers' *"not right now"* rows were dead mechanics — which also made Alex's Badge Audit personal mission unreachable, because deferring the side-quest hub is the only way past it. `commit` defaults to **false**; the single `true` call site is `_interact()`. Every tool harness calls it as a query and now gets one.
- **A SIDE QUEST STARTED BY A ROOM PROP BYPASSES THE ROUTER'S GATES.** Alex's six IT side quests are held behind `act2_complete` inside `_getAlexSideQuestDialog` ("only available after the Henderson Trust arc is resolved"), but **Server Room Secrets is started by an interactable**, `server_rack_inspect`, which gated only on `met_alex_it` — so a fresh save could start it before the briefing and before a single Henderson (playtest, 2026-08-15). It now routes through an **appended** node 10 that adds the `act2_complete` term; the four flavour lines still read at any act, only the quest waits. Same class: `printer_quest_started` and `server_secret_started` are both set by Act-1 flavour props and both pinned Alex's routing ABOVE `act4_trigger`, the sole setter of `act3_complete` — `_alexMainPathPending()` (story beat available **or** holding the Archive evidence with `act3_complete` unset) is the one predicate both exemptions now use.
- **NPC conditional spawning**: set `condition: { flag: 'x' }` or `condition: { notFlag: 'x' }` in the room data NPC entry. NPCs with any condition initialize hidden; no extra code needed. Multiple entries with the same `id` but different conditions are used for state-dependent dialogs (e.g., the Archive janitor has 5 conditional entries covering each quest stage). **Limitation**: a single condition object supports exactly one `flag` AND/OR one `notFlag`. For compound conditions (e.g., "all 4 coworkers met"), add a DERIVE row to `src/data/story/graph.js` and gate on the flag it writes.
- **Reception roguelite loop**: `ClientGenerator` procedurally generates enemies. After victory, `ClientReviewState` is pushed. `bossAnger` player flag drives branching. On client acceptance: AUM earned = max(50, floor(assets × 0.01)). Beneficiary chains: use `generateBeneficiaryChain()` + `applyChainModifiers()`.
- **AUM currency**: stored in `player.stats.aum`. Earned from accepted reception clients. Spent in `ShopState`. Permanent stat upgrades from the shop modify `player.stats` directly.
- **Achievements**: `AchievementManager.check(player, ctx)` is called after key game events. The `ctx.event` string is matched against each achievement's `check` function. For `client_accepted`, ctx must also carry `assets` (number) and `attributes` (array with `.positive` booleans) for the Dream Client / High Roller checks. `client_declined` fires in the decline branch of the reception loop. Act-completion achievements fire from the `flag-set` EventBus listener in ExplorationState via the `ACT_ACHIEVEMENT_FLAGS` array — no explicit event string needed, just call `check(player, {})` when any of those flags is set.
- **Shop category flags**: `ShopState` sets `bought_category_consumable`, `bought_category_upgrade`, and `bought_category_decor` on `player` after each successful purchase. These drive the Supply Run achievement.
- **Janitor riddle retry pattern**: Each riddle dialog starts with a `condition` node checking `riddle_X_attempted`. On first entry (`ifFalse`) it sets that flag then falls through to the intro text. On retry (`ifTrue`) it jumps directly to the riddle question, skipping the intro. Wrong-answer paths end without setting the `janitor_riddle_X_done` flag, so the player can re-enter and try again. When adding new riddle dialogs, always insert this two-node gate at positions 0 and 1.
- **Auto-save**: `ExplorationState._autoSave()` calls `SaveManager.save(player.serialize())` and shows a toast every time. Fires on every room transition and every story combat victory.
- **Quest objective display**: The HUD objective text comes from `_getStoryObjective()` in `ExplorationState` (flag-based hardcoded strings), **not** from `quests/index.js` or `QUEST_OBJECTIVES`. Edit `_getStoryObjective()` to change what the player sees.
- **Leveling**: 15 levels, exponential XP curve. Level 1→2 costs 325 XP (~5 reception fights at 65 XP each). Story bosses alone yield ~835 XP max, landing the player around level 4. Levels 5–10 require roguelite grinding; 11–15 are completionist.
- **Henderson difficulty**: Karen/Chad/Grandma are intentionally tough to force roguelite grinding. Karen requires ~level 3–4, Chad ~5–6, Grandma ~7–8. Each has 2 additional combat phases at 50% and 25% HP. **That intent does not currently reproduce, and the reason is measured** (`node tools/_l-balance.mjs --diag`): at its designed level a story boss needs between **7.5 and 45.1 enemy turn ATTEMPTS** to kill Andrew at its own damage-per-turn, and is granted between **2.5 and 9.8**. Grandma at 8 needs 45 and gets 4.9; Andrew finishes `chad@6` and `grandma@8` having never dropped below **89 %** of his health bar. Two things take those turns: **denial** (23–61 % of attempts are fizzled or Broken) and **quiet turns** (of the survivors, 30–74 % deal zero damage, because the phase lists are mostly heals, buffs, debuffs and stuns and the picker draws from them flat). **`dmg/hit` is not the problem** — Grandma's landed attack does 72.8 to a 172 HP player. **Do not answer this with enemy stats**: boss ability power ×1.15 moves the 21-cell PIP floor 12.16 pp with 21 cells down and 0 up. The priced answer is `.claude/plans/l-run/BALANCE-PROPOSAL.md`, dark pending the producer.
- **WIN RATE IS THE WRONG DIFFICULTY METRIC HERE and the harness now carries two better ones.** It saturates at 100 % long before a fight stops being frightening — the shipped ladder reads 98.7–100 % competent at-level, which cannot distinguish "tense" from "untouched". `tools/_l-balance.mjs` reports **low-water** (the lowest fraction of maxHP Andrew ever stood at, sampled after every action, with a DEFEAT counted as 0 so a candidate cannot look safer by killing more often) and **near-death** (share of runs that touched 25 %). Shipped: low-water 45.6–89.4 %, near-death 0.0–9.5 %. Also **`dmg/T`**, damage per enemy turn ATTEMPT, so a denied turn correctly scores zero.
- **Ability tags and weaknesses**: Karen = weak `legal`, resists `social`; Chad = weak `social`, resists `legal`; Grandma = weak `audit`, resists `social`. Tag the appropriate ability and the 1.5× bonus fires automatically. **These are the BASE (phase 0) rows only** — see THE PIVOT above; Chad, Grandma, Meredith and the Regional Director change which area they are open to when their phase changes, and the HUD announces it for free.
- **Stat theming**: HP = Patience, MP = Coffee, ATK = Assertiveness, DEF = Composure, SPD = Bureaucratic Efficiency. Player name hardcoded as `'Andrew'`.
- **Dialog data gotchas**: `give_item` actions use `item` field (not `itemId`). Choice nodes use `prompt` field for the question text (not `text`).
- **Dialog action nodes** (full list): `set_flag`, `start_combat`, `give_item`, `heal`, `quest_update`, `give_xp` (calls `player.gainXP(node.xp)`), `modify_stat` (increments `player.stats[node.stat]` by `node.amount`, min 1), `recruit_ally`, `unlock_ally_ability`.
- **`stage` nodes — CUTSCENE STAGING** (`{ type: 'stage', beats: [...], next?, concurrent? }`). A sixth node TYPE beside `text`/`choice`/`condition`/`action`/`end`. Full grammar and the seven degradation rules are in the header of **`src/world/StageDirector.js`**; read it before authoring. The essentials:
  - Beats in one node run in **parallel** unless a beat sets `after: <n>`; sequence a scene by interleaving `stage` nodes with `text` nodes (line, move, line).
  - **TWO PLAYBACK MODES, chosen per node — pick per beat, not per scene.**
    - **SCHEDULED** (default): the dialog box **hides**, the dialog **blocks**, the actors move, the next line appears when they arrive. Use it when the movement *is* the beat — an entrance, a sit-down the next line refers to, a walk-out that ends a scene.
    - **CONCURRENT** (`concurrent: true`): the box **stays up** and the dialog advances immediately; the beats play **underneath the text**. Use it for motion that should read as happening while someone talks — background bodies settling, an ally crossing the room during another character's line, a flight under the narration that announces it.
    - **`wait: false` is NOT concurrent mode and never was.** It only tells the *gate* not to wait for that beat; the node still hides the box for a frame or for however long its other beats run. The board meeting had `wait: false` on seven step-backs and still blanked **eleven times in two minutes** — which is exactly what the producer meant by "the dialog boxes are blocking movement from working properly in the background".
    - **THE UNPAUSE IS NARROW AND MUST STAY NARROW.** Concurrent mode works only because `StageDirector` ticks the animators of the actors *it* is driving and nothing else, from `main.js`. `ExplorationState.update()` stays asleep in **both** modes, so player input, NPC patrols, interactable proximity and exit tiles are all still frozen. Never "fix" a concurrent beat by unpausing `ExplorationState` — that hands the player their body back in the middle of their own cutscene.
    - Shipped mix, as a worked example: `secret_ending` 57/60/62 concurrent (reaction turns, the cane rise, the Regional Manager's flight) with 56/58/59/61 scheduled (Andrew's approach, Skip out of his chair, the sit-down, the four-body march); `board_meeting` concurrent everywhere **except** the six ally step-OUTs, because stepping forward to address a board is the beat and the line lands on arrival; `the_firm_ambush` fully scheduled — an entrance should own the frame.
  - Verbs: `walkTo` · `face` · `sit` · `stand` · `exit` · `gesture` · `pose` · `expression` · `spawn`/`spawnAt` · `teleportTo` · `show` · `speed` · `hold` · `wait: false` (don't block the dialog).

- **`tools/_fr1-dialog-indices.mjs` is the append-only law checked DIRECTLY.** `_g-stage-verify` signs NODE CONTENT, so an authorized in-place prose edit trips it and its FAIL cannot tell a producer-ruled rewording from a node inserted mid-tree that silently renumbered 80 jump targets. And it **exits 0 whether it passes or fails** — read the last line, never the exit code. Its counterpart is honest the other way: an in-place prose edit makes `_g-stage-verify` exit 1 BY DESIGN, and the pair is the discriminator — stage-verify red plus `_fr1` PASS means only text moved.

## Playwright harness gotchas (tools/)

Each of these has cost a round of evidence that turned out to be measuring the harness.

- **`import('/src/core/Engine.js')` inside `page.evaluate()` can hand you a SECOND, uninitialised Engine.** Vite serves the running app's copy with an HMR cache-buster (`/src/core/Engine.js?t=1785837754280`) the moment anything in the tree has been edited that session; the bare specifier is a different URL, so you get a fresh module whose `scene` and `renderer` are both `null`. Silent, because most call sites null-guard (`_g-wall-shoot`'s `--zoom` loop does exactly this and simply no-ops). Reach the live singleton through the object graph instead — walk `window.__explore.player.mesh` up to its root for the scene.
- **In-page luminance probes read 0.** The renderer does not set `preserveDrawingBuffer`, so `drawImage(canvas, …)` after the frame is composited returns black. Measure the saved PNG (`tools/_g-lum.mjs`), not the canvas.
- **NPC `conditionFn` is only evaluated while `ExplorationState` is the TOP state.** Any dialog a flag-set listener pushes freezes every conditional NPC hidden, which reads exactly like "the NPC is missing". When auditing conditional spawns, call `npc.conditionFn(player.flags)` directly — same predicate, no state-stack artifact. Sampling `npc.visible` inside the same `page.evaluate()` that just called `_loadRoom()` is also a lie: `EntityManager.update()` has not run yet.
- **Shoot the END of a staged scene, not just its middle.** `_g-cut-shoot` takes `final` and then `settled` (+1.4 s) for exactly this reason — the board meeting emptied itself in the window between them and three evidence packages missed it. Its `advances` cap must clear the whole tree (`board_meeting` needs ~189 Enter presses; the recipe said 140, so every earlier take's `final` frame still had the dialog box up).
- `InputManager` diffs key state between frames — a zero-delay `keyboard.press()` is invisible. Hold every tap ~100–210 ms.
- **A CAPTURE THAT SPANS MINUTES MUST NOT RUN ON `npm run dev`.** Vite full-reloads the page whenever anything in the watched tree changes, and on this repo *another lane is usually editing `src/`*. Measured cost: three separate multi-turn combat captures were destroyed mid-run (`page.evaluate: Execution context was destroyed, most likely because of a navigation`), and one of them was mistaken for a quality-tier fault before the cause was found. **Build once and shoot against `npx vite preview`** — it serves `dist/` off disk and watches nothing. `?dev`, `?fixture=`, `?fight=` and `?qtier=` all work in the production bundle.
- **…and then the preview server becomes the identity hazard.** `dist/` holds whatever was last built, so reverting `src/` does NOT change what the browser is served. Two captures were tagged `before` against an `after` bundle for exactly this reason and had to be deleted. **A/B harnesses must assert BUILD IDENTITY from live state, not from the tag they were given** — `tools/_l-fight-ab.mjs` reads `engine.getPressAdvantageCost()` (37 on the baseline, 49 with the balance proposal applied) and exits 1 if it disagrees with its own `--tag`.
