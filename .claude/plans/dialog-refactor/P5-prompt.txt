=== THE ONE THING THAT WILL BREAK IT IF YOU GET IT WRONG ===
**DERIVE IS AN ORDERED SINGLE PASS, NOT A FIXPOINT.** The current code is one top-to-bottom
pass through _refreshStoryProgress. `intern_at_desk` is computed at line ~3844 and READS
`board_meeting_closed`, which is not derived until line ~3918. So within a single call the
intern flags deliberately lag one call behind. If your evaluator runs to a fixpoint, the
intern flags change value one call earlier than the shipping game and the A/B harness will
diverge. Evaluate DERIVE ONCE, IN ARRAY ORDER, and keep the array in the same order the
source computes them. Then run the act ladder, then the quest-id ladder — that is also the
current order (_syncActFromFlags is called AFTER the derives, at line ~3935).

Two more order facts to preserve exactly:
 - A `latch` rule only ever writes true, and only when the flag is currently false.
 - A `live` rule writes its boolean EVERY call, both polarities. There are exactly five
   (intern_at_desk, intern_confronting, intern_desk_idle, intern_rehearsing,
   intern_rally_ready) and they are the only two-way flags in the block.
