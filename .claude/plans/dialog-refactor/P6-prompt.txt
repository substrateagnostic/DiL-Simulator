=== THE MODEL ===
State = a flag set. Core = a monotone forward closure: repeat { apply DERIVE to fixpoint;
collect every grant whose precondition holds; add them } until nothing changes. NOTE: the
simulator's closure IS a fixpoint — that is correct here and is deliberately different from
the runtime evaluator's single ordered pass (which P5 preserved for behaviour identity).
Say so in the tool's header so nobody "fixes" one to match the other.

Harvest grants from three sources and union them (DESIGN 4.5):
 1. the compiled dialog corpus — every set_flag node and every choice `flag`, with the
    IN-TREE PATH CONDITION that reaches it (walk the tree from node 0; a set_flag behind a
    condition node inherits that condition; a set_flag behind a choice arm is unconditional
    from the player's point of view because the player can pick any visible arm)
 2. AUTO_GRANTS patterns
 3. CODE_GRANTS
A scene's grants only count once the scene is REACHABLE (its route/trigger precondition
holds), so scene reachability and flag reachability are computed together in the same
closure. That coupling is the whole value of the tool.

=== THE SEVEN CHECKS ===
A  ACT COMPLETABILITY — every ACTS[].when flag is in the closure from a genuinely fresh
   save (empty flag set). This is the check the act5_trigger bug turned red.
B  FLAG REACHABILITY — every flag READ anywhere (dialog condition nodes and choice
   requires/requiresNot; room NPC `condition`; furniture `condition`; GATES.requires; every
   route's `when`; every DERIVE `when`; the objective strings) is in the closure, or in
   CODE_GRANTS, or has a NEVER_SET row with a reason.
C  SCENE REACHABILITY — every scene id in the compiled corpus is the `then` of some route,
   the `scene` of some trigger, an NPC `dialogId` in rooms, an interactable `dialogId`, an
   encounter pre/postDialogId, reachable through the ['ladder'] resolver's template forms
   (neutral_<npc>, <enc>_retry, <npc>_intro, <npc>_return, <npc>_act2..7), or carries a
   SCENE_DISPOSITION row. Report never-wired and severed SEPARATELY (orphan-scenes.md §3
   says why: one is a scope question, the other is a regression).
D  GATE CLOSABILITY — every GATES[].requires flag is in the closure, and is reached BEFORE
   the first trigger or route that needs the room behind it.
E  NO SPEND-BEFORE-GRANT — for every trigger, either once:'scene', once:'always', or a
   named `waiver`. Print every waiver by name in the summary so the count only goes down.
F  THE EXPIRY CHECK (ordering, not just closure) — for every grant G whose precondition
   contains a negative term NOT f where f is itself in the closure, assert a topological
   order exists placing G before f. This is the check that catches "four ally missions
   expired at act6_complete" (the bug the comment at ExplorationState.js:~3044 records).
G  ROUTE SHADOWING — for every row in DIALOG_ROUTES (it may not exist yet — P7 builds it;
   if src/data/story/routes.js is absent, implement check G against the rule set you CAN
   see and make it a no-op-with-a-notice rather than a crash), assert there exists a
   satisfying assignment of the flags it reads under which no EARLIER rule fires. A rule
   with no such assignment is dead and is reported by id.

Output contract: human-readable, one line per finding, file:line where known; exit 1 on any
failure; `--report=<file>` writes machine-readable JSON.

=== --selftest : SEVEN MUTATIONS, SEVEN REDS ===

per check — and asserts THAT CHECK goes red. It must print a table: check, mutation applied,
expected RED, observed. Exit 1 if any mutation fails to turn its check red. A gate that has
never been seen to fail is not a gate. Suggested mutations (use your judgement, but each
must be a REALISTIC defect, not a syntactic wrecking ball):
 A  delete the single grant of act4_complete (act5_trigger's set node)

 E  turn a once:'scene' trigger into once:'flag:x' with no waiver
 F  add a negative precondition that expires a grant it needs
